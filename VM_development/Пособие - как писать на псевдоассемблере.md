## Введение 

Система машинных команд является важнейшей частью архитектуры виртуальной машины VM32, так как с их помощью производится непосредственное управление работой интерпретатора.  VM32 спроектирована с акцентом на простоту и единообразие форматов.

При знакомстве с системой машинных команд VM32 необходимо учитывать два аспекта — собственно набор машинных команд и правила представления этих команд на уровне интерпретатора, то есть формат машинных команд. Виртуальной машине понятен только один формат — 32-битные инструкции фиксированной длины. Машинные команды представляют собой сформированные по определенным правилам последовательности битов.

Для облегчения процесса разработки программ был создан ассемблер VM32, как символический аналог машинного языка. Существует взаимно однозначное соответствие машинных команд и команд ассемблера. Понимание правил формирования машинных команд из команд ассемблера является одним из необходимых условий не только для изучения языка ассемблера VM32, но и для понимания логики работы виртуальной машины в целом.

## 1. Логическая структура команды

Машинная команда VM32 — это 32‑битное слово, состоящее из набора полей фиксированных размеров. Логически команда содержит три класса элементов:

1. **Код операции (Opcode)** — указывает, какое действие должно быть выполнено.
2. **Операнды** — объекты, над которыми производится действие (регистры, память, константы).
3. **Атрибуты/флаги** — служебные биты, уточняющие интерпретацию полей (например, режим immediate).
    

Понимание назначения каждого поля и правил их кодирования необходимо для корректной реализации ассемблера и декодера интерпретатора.

### Формат 32‑битной инструкции

![[Форма команды.drawio.png]]
Рис. 1 - Формат машинной команды

Физически каждая инструкция занимает ровно 32 бита (4 байта). Биты нумеруются от 31 (старший) до 0 (младший). Поля расположены следующим образом:

- **Биты 31–25 (7 бит)** — `Opcode` (0..127)
    
- **Биты 24–17 (8 бит)** — `A` — регистр назначения (результат операции) (0..255)
    
- **Биты 16–9 (8 бит)** — `B` — первый источник (регистр) (0..255)
    
- **Бит 8 (1 бит)** — `IMM` — флаг типа второго операнда (0 = регистр, 1 = immediate)
    
- **Биты 7–0 (8 бит)** — `C/IMM` — второй операнд: регистр или младшая часть immediate
    

Формат выбран так, чтобы обеспечить баланс между числом регистров (широкие поля A, B) и компактностью immediate‑поля. Фиксированная длина обеспечивает простоту адресации инструкций и детерминированность декодирования.

> **Замечание.** Внутри ассемблера обычно представление immediate хранится с дополнительным контекстом (тип, длина). На уровне машинного слова мы сохраняем лишь младший байт и отдельный флаг `IMM`.


Каждая инструкция занимает ровно **32 бита**:

###  Endianness и упаковка слова

VM32 использует порядок байтов **little‑endian** при хранении слова в памяти и в бинарных образах. Это означает: младший байт слова (биты 7..0) располагается по наименьшему адресу.

В псевдокоде упаковка полей в 32‑битное слово выглядит так:

```c
uint32_t word = ((uint32_t)opcode << 25) |
                ((uint32_t)A << 17) |
                ((uint32_t)B << 9) |
                ((uint32_t)IMM << 8) |
                ((uint32_t)C & 0xFF);

```


При записи в память слово разбивается на байты:

```c
bytes[0] = word & 0xFF;           // байт 0 — младший
bytes[1] = (word >> 8) & 0xFF;    // байт 1
bytes[2] = (word >> 16) & 0xFF;   // байт 2
bytes[3] = (word >> 24) & 0xFF;   // байт 3 — старший
```

Эта организация обеспечивает совместимость с большинством инструментов отладки и простоту визуального мониторинга бинарного образа.
# 2. Мнемоники и таблица опкодов

## 2.1 Определение OpEntry

Каждая инструкция VM32 представлена в ассемблере структурой `OpEntry`, которая связывает символическую мнемонику с числовым кодом операции и определяет политику использования операндов:

```c
typedef struct {
    const char *name;    // символическое имя команды (мнемоника)
    int code;            // числовой код операции (0-127)
    CFlags cflags;       // флаги политики для операнда C
} OpEntry;
```

**Поля структуры:**

- **name** — символическая мнемоника команды, используемая в исходном коде программы (например, `"add"`, `"sub"`, `"jmp"`). Регистр символов не имеет значения — ассемблер выполняет сравнение без учёта регистра через `strcasecmp()`.
    
- **code** — числовой код операции, который будет закодирован в битах 31-25 результирующей инструкции. Диапазон значений: 0-127 (7 бит).
    
- **cflags** — битовые флаги, определяющие допустимые режимы использования операнда C для данной команды.
    

## 2.2 Политика для операнда C (cflags)

Система флагов `CFlags` управляет тем, какие типы операндов допустимы в поле C конкретной инструкции:

```c
typedef enum {
    CFLAG_NONE = 0,              // без специальных требований
    CFLAG_ALLOW_IMM = 1<<0,      // разрешён immediate-операнд (#число)
    CFLAG_C_MUST_REG = 1<<1      // C обязан быть регистром
} CFlags;
```

### Таблица 2.2.1 Описание флагов политики

|Флаг|Значение|Описание|Применение|
|---|---|---|---|
|`CFLAG_NONE`|0|Нет специальных ограничений|Операции, не использующие C|
|`CFLAG_ALLOW_IMM`|0x01|Разрешён immediate в поле C|Арифметика, логика, сравнения|
|`CFLAG_C_MUST_REG`|0x02|C обязан быть регистром (immediate запрещён)|Адресные операции, специальные команды|

**Логика проверки в ассемблере:**

```c
// Проверка разрешения immediate
if (Cop.type == OP_IMM && !(opent->cflags & CFLAG_ALLOW_IMM)) {
    fprintf(stderr, "Line %lu: Opcode '%s' does not allow immediate in C\n",
            lineno, opent->name);
    return ERROR;
}

// Проверка требования регистра
if ((opent->cflags & CFLAG_C_MUST_REG) && Cop.type == OP_IMM) {
    fprintf(stderr, "Line %lu: Opcode '%s' requires C to be a register\n",
            lineno, opent->name);
    return ERROR;
}
```

### Примеры использования

**1. Операции, допускающие immediate (`CFLAG_ALLOW_IMM`):**

```assembly
ADD R0, R1, #10       ; корректно: арифметическая операция
SUB R5, R3, #-5       ; корректно: отрицательная константа
AND R2, R2, #0xFF     ; корректно: битовая маска
```

**2. Операции, требующие регистр (`CFLAG_C_MUST_REG`):**

```assembly
CONCAT R0, R1, R2     ; корректно: R2 содержит адрес строки
SEL R0, R1, R2        ; корректно: R2 содержит базовый адрес
CONCAT R0, R1, #100   ; ОШИБКА: immediate недопустим
```

**3. Операции без операнда C (`CFLAG_NONE`):**

```assembly
NOT R0, R1            ; унарная операция, C не используется
SQRT R0, R1           ; математическая функция одного аргумента
```

### 2.3.2 Арифметические операции (0-16)

Арифметические инструкции выполняют математические вычисления над 32-битными беззнаковыми целыми числами или числами с плавающей точкой (для трансцендентных функций).

**Базовая арифметика:**

- `ADD`, `SUB`, `MUL` — основные операции, поддерживают immediate
- `DIV`, `MOD` — деление с защитой от деления на ноль (возвращают 0)
- `EXPT` — возведение в степень через `pow()`

**Унарные функции:**

- `ABS` — модуль числа (интерпретируется как знаковое `int32_t`)
- `SQRT` — квадратный корень
- `LN`, `LOG`, `EXP` — логарифмические и экспоненциальные функции

**Тригонометрия:**

- `SIN`, `COS`, `TAN` — прямые тригонометрические функции
- `ASIN`, `ACOS`, `ATAN` — обратные тригонометрические функции

**Примечание:** Результаты функций с плавающей точкой усекаются до `uint32_t`.

### 2.3.3 Логические операции (17-20)

Побитовые логические операции над 32-битными словами:

```assembly
AND R0, R1, #0xFF     ; выделение младшего байта
OR  R0, R1, #0x80     ; установка старшего бита байта
XOR R0, R1, R2        ; побитовое исключающее ИЛИ
NOT R0, R1            ; инверсия всех битов
```

### 2.3.4 Операции сравнения (21-26)

Все операции сравнения записывают **булево значение** (0 или 1) в регистр A:

```assembly
EQ R0, R1, #100       ; R0 = (R1 == 100) ? 1 : 0
GT R0, R1, R2         ; R0 = (R1 > R2) ? 1 : 0
LE R0, R1, #50        ; R0 = (R1 <= 50) ? 1 : 0
```

Эти инструкции удобны для использования совместно с условными переходами:

```assembly
GT R0, R5, #10        ; проверка R5 > 10
JMP_IF R0, .label, R0 ; если истина, переход на .label
```

### 2.3.5 Работа со временем и датой (27-38)

Инструкции для получения текущего системного времени в различных форматах:

**Комплексные значения:**

- `TIME` — секунды с начала текущего дня (0-86399)
- `DATE` — текущая дата в формате YYYYMMDD (например, 20260120)
- `TOD` — время суток в формате HHMMSS (например, 143025 = 14:30:25)
- `DT` — комбинированное значение даты и времени

**Отдельные компоненты:**

- `YEAR`, `MONTH`, `DAY` — компоненты даты
- `HOUR`, `MINUTE`, `SECOND` — компоненты времени

**Арифметика времени:**

```assembly
TIME R0              ; R0 = текущее время (секунды)
ADD_TIME R1, R0, #3600  ; R1 = R0 + 1 час
SUB_TIME R2, R1, #60    ; R2 = R1 - 1 минута
```

### 2.3.6 Строковые операции (39-46)

Строки в VM32 хранятся в памяти как нуль-терминированные последовательности байтов (C-style strings). Все строковые операции выполняют **безопасные** операции с проверкой границ памяти.

**Базовые операции:**

```assembly
LEN R0, R1            ; R0 = длина строки по адресу R1
CONCAT R0, R1, R2     ; строка[R0] += строка[R2] (in-place)
```

**Извлечение подстрок (in-place модификация):**

```assembly
LEFT R0, R1, #10      ; оставить первые 10 символов строки[R1]
RIGHT R0, R1, #5      ; оставить последние 5 символов
MID R0, R1, #3        ; сдвинуть начало строки на 3 позиции
```

**Редактирование:**

```assembly
INSERT R0, R1, #5     ; вставить строку[R1] в позицию 5 строки[R0]
DELETE R0, R1, #3     ; удалить 3 символа начиная с позиции R1
REPLACE R0, R1, #2    ; заменить часть строки[R0] на строку[R1]
```

**Важно:** Операции `CONCAT`, требующие двух адресов строк, используют `CFLAG_C_MUST_REG`, так как C должно содержать адрес второй строки.

### 2.3.7 Таймеры IEC (47-49)

Таймеры реализуют стандартное поведение IEC 61131-3 с детекцией фронтов входных сигналов:

**TON (Timer ON-delay):**

```assembly
; id = R0, input = R1, preset_time = #1000 (мс)
TON R0, R1, #1000     ; R0 получит 1 через 1000 мс после R1=1
```

Выход устанавливается в 1 через заданное время после установки входа в 1.

**TOF (Timer OFF-delay):**

```assembly
TOF R0, R1, #500      ; R0 сбросится в 0 через 500 мс после R1=0
```

Выход сбрасывается в 0 через заданное время после сброса входа в 0.

**TP (Timer Pulse):**

```assembly
TP R0, R1, #200       ; импульс длительностью 200 мс по фронту R1
```

Генерирует импульс фиксированной длительности по переднему фронту входного сигнала.

**Общие принципы:**

- Регистр A содержит ID таймера (0-15)
- Регистр B содержит входной сигнал (0 или ≠0)
- Операнд C содержит preset time (уставку) в миллисекундах
- После выполнения регистр A содержит состояние выхода (Q)

### 2.3.8 Счётчики IEC (50-52)

Счётчики реализуют стандартное поведение IEC 61131-3 с детекцией фронтов:

**CTU (Count Up):**

```assembly
CTU R0, R1, #100      ; счёт вверх до 100
                      ; R0 = (count >= 100) ? 1 : 0
```

Инкремент по переднему фронту входа (0→1), выход Q=1 при достижении preset.

**CTD (Count Down):**

```assembly
CTD R0, R1, #0        ; счёт вниз до 0
                      ; R0 = (count <= 0) ? 1 : 0
```

Декремент по переднему фронту входа, выход Q=1 при достижении preset.

**CTUD (Count Up/Down):**

```assembly
CTUD R0, R1, R2       ; R1 = up, R2 = down
                      ; R0 = текущее значение счётчика
```

Реверсивный счётчик: инкремент по фронту up, декремент по фронту down.

**Примечание:** `CTUD` требует `C_MUST_REG`, так как нужны оба входа (up и down).

### 2.3.9 Выбор и ограничение (53-55)

**LIMIT:**

```assembly
LIMIT R0, R1, #100    ; ограничить R0 диапазоном [R1, 100]
```

Ограничивает значение регистра A между минимумом (B) и максимумом (C).

**SEL (Select):**

```assembly
SEL R0, R1, R2        ; выбор: R0 = R1 ? mem[R2] : mem[R2+4]
```

Выбирает одно из двух 32-битных слов из памяти по условию. Базовый адрес в R2, условие в R1.

**MUX (Multiplexer):**

```assembly
MUX R0, R1, #3        ; R0 = mem[R1 + 3*4]
```

Выбирает один элемент из массива 32-битных слов. Базовый адрес в B, индекс в C.

### 2.3.10 Управление потоком (56-61)

**JMP (безусловный переход):**

```assembly
JMP #100              ; PC = 100 (immediate-адрес, signed 8-bit)
JMP R0, R5, R0        ; PC = R5 (адрес из регистра B)
```
**Важно:** Адрес перехода берётся из **регистра B** (не A), либо из immediate (поле C).

**JMP_IF (условный переход):**

```assembly
GT R2, R3, #5         ; R2 = (R3 > 5) ? 1 : 0
JMP_IF R0, #100, R2   ; если R2≠0 (условие из C!), перейти на 100
```

Переход выполняется, если **регистр C ≠ 0** (не регистр A!). Адрес берётся из immediate (signed 8-bit) или из **регистра B**.

**JMP_IF_NOT (инверсный условный переход):**

```assembly
EQ R2, R1, #0 JMP_IF_NOT R0, #50, R2 ; если R2=0, перейти на 50
```

Переход выполняется, если **регистр C = 0**. Адрес — из immediate или регистра B.

**EXIT (завершение с кодом):**

```assembly
EXIT R7, R0, #0       ; если R7≠0: код=R7, иначе код=0
EXIT R0, R0, #42      ; если R0=0: код=42, иначе код=R0
```

Специальная семантика: если **значение регистра A ≠ 0**, код выхода = значение регистра A. Иначе код выхода = immediate (поле C, sign-extended).

**HALT:**

```assembly
HALT                  ; полная остановка VM
```

Останавливает выполнение виртуальной машины. По умолчанию ассемблер преобразует `HALT` в `EXIT 0` (см. раздел 3.4).

**NOP:**

```assembly
NOP                   ; нет операции
```

Пустая инструкция, не выполняет никаких действий. Полезна для выравнивания кода или placeholder'ов.

## 2.4 Особые опкоды: HALT и EXIT

### 2.4.1 Различие между HALT и EXIT

В VM32 существуют две инструкции для завершения программы, которые имеют разную семантику:

**EXIT (код 59):**

- Завершает выполнение программы с заданным кодом возврата
- Код возврата может быть взят из immediate или регистра
- Устанавливает глобальную переменную `vm_exit_code`
- Корректное завершение для пользовательских программ

**HALT (код 60):**

- Экстренная остановка виртуальной машины
- Не передаёт код возврата
- Используется для низкоуровневой диагностики
- В большинстве случаев не рекомендуется для обычных программ

### 2.4.2 Автоматическое преобразование HALT → EXIT 0

По умолчанию ассемблер VM32 автоматически преобразует мнемонику `HALT` в инструкцию `EXIT` с кодом возврата 0:

```c
// В ассемблере (asm2bin.c):
if (!raw_halt && strcasecmp(tok, "halt") == 0) {
    tok = "exit";  // переписываем мнемонику
    // дальнейшая обработка идёт как для EXIT
}
```

**Поведение при ассемблировании:**

```assembly
; Исходный код:
HALT

; Компилируется как:
EXIT R0, R0, R0    ; эквивалентно EXIT с кодом 0
```

**Сообщение ассемблера:**

```
Assembled program.asm -> program.bin (HALT mapped to EXIT 0 by default)
```

### 2.4.3 Флаг --raw-halt

Для сохранения оригинальной инструкции `HALT` используйте флаг командной строки `--raw-halt`:

```bash
./asm2bin program.asm program.bin --raw-halt
```

**Эффект:**

- Мнемоника `HALT` компилируется в настоящий опкод 60
- Не происходит автоматической замены на `EXIT`
- Программа завершается через `op_halt()` без передачи кода возврата

**Сообщение ассемблера:**

```
Assembled program.asm -> program.bin (RAW HALT mode enabled)
```

**Когда использовать `--raw-halt`:**

- Отладка внутреннего состояния VM
- Тестирование обработки экстренной остановки
- Низкоуровневая диагностика

**Когда использовать обычный режим:**

- Нормальное завершение пользовательских программ
- Передача кодов возврата операционной системе
- Интеграция с внешними скриптами

### Таблица 2.4.4: Сравнение HALT и EXIT

|Характеристика|EXIT|HALT (raw)|
|---|---|---|
|Код операции|59|60|
|Код возврата|Настраиваемый (A или imm)|Не устанавливается|
|Ассемблер по умолчанию|Используется для `HALT`|Требует `--raw-halt`|
|Применение|Обычное завершение|Экстренная остановка|
|Глобальная переменная|`vm_exit_code`|Не используется|
|Флаг|`running = false`|`running = false`|

# 3. Синтаксис исходного файла (asm)

## 3.1 Общие правила лексики

Исходный файл ассемблера VM32 представляет собой текстовый файл, содержащий по одной инструкции в строке. Ассемблер выполняет построчный разбор с применением простых лексических правил.

### 3.1.1 Разделители токенов

Токены (мнемоники и операнды) могут разделяться следующими символами:

- **Пробел** ( , ASCII 0x20)
- **Табуляция** (`\t`, ASCII 0x09)
- **Запятая** (`,`, ASCII 0x2C)

Разделители могут комбинироваться в произвольном порядке:

```assembly
; Все варианты корректны:
ADD R0, R1, R2
ADD R0,R1,R2
ADD   R0   R1   R2
ADD R0  ,  R1  ,  R2
```

**Реализация токенизации:**

```c
char *tok = strtok(p, " \t,");
```

### 3.1.2 Комментарии

Ассемблер поддерживает два стиля комментариев:

**1. Комментарии в стиле ассемблера (`;`):**

```assembly
; Это полная строка-комментарий
ADD R0, R1, R2    ; инлайн-комментарий
```

**2. Комментарии в стиле скриптов (`#`):**

```assembly
# Это также комментарий
SUB R3, R4, R5    # альтернативный стиль
```

**Обработка комментариев:**

```c
// Удаление инлайн-комментариев
char *cpos = strpbrk(p, ";#");
if (cpos) *cpos = '\0';

// Пропуск строк, начинающихся с комментария
if (*p == ';' || *p == '#') continue;
```

**Примечание:** Символы `;` и `#` внутри строковых литералов не поддерживаются в текущей версии ассемблера.

### 3.1.3 Пустые строки

Пустые строки и строки, содержащие только пробельные символы, игнорируются:

```assembly
ADD R0, R1, R2

                  ; пустая строка выше пропущена
SUB R3, R4, R5


MUL R6, R7, R8    ; множественные пустые строки также допустимы
```

**Проверка пустых строк:**

```c
// Пропуск пробелов в начале строки
while (*p && isspace((unsigned char)*p)) p++;

// Пропуск пустых строк
if (*p == '\0' || *p == '\n') continue;
```

### 3.1.4 Регистронезависимость

Мнемоники команд не чувствительны к регистру символов:

```assembly
; Все варианты эквивалентны:
ADD R0, R1, R2
add R0, R1, R2
Add R0, R1, R2
AdD R0, R1, R2
```

**Реализация:**

```c
if (strcasecmp(tok, "halt") == 0) { ... }
```

**Примечание:** Регистры и immediate-значения **регистрозависимы** в префиксе (`R` и `#` должны использоваться в верхнем регистре), но номера/значения могут быть в любом регистре при использовании hex (`0x`/`0X`).

## 3.2 Формат строки инструкции

Каждая строка содержит одну инструкцию в следующем формате:

```
мнемоника [операнд_A] [операнд_B] [операнд_C]
```

**Компоненты:**

1. **Мнемоника** — обязательный символический код операции
2. **Операнд A** — необязательный, регистр назначения (по умолчанию R0)
3. **Операнд B** — необязательный, первый операнд-источник (по умолчанию R0)
4. **Операнд C** — необязательный, второй операнд (по умолчанию R0 или #0)

### Примеры различных форматов

**Полная форма (все операнды указаны):**

```assembly
ADD R10, R5, R3       ; R10 = R5 + R3
MUL R0, R1, #2        ; R0 = R1 * 2
GT R7, R8, #100       ; R7 = (R8 > 100) ? 1 : 0
```

**Сокращённая форма (операнды по умолчанию):**

```assembly
NOP                   ; эквивалентно NOP R0, R0, R0
HALT                  ; эквивалентно HALT R0, R0, R0 (или EXIT R0, R0, R0)
EXIT                  ; эквивалентно EXIT R0, R0, #0
```

**Частичная форма (некоторые операнды указаны):**

```assembly
NOT R5, R3            ; R5 = ~R3, операнд C не используется
SQRT R2, R10          ; R2 = √R10
```

### Обработка отсутствующих операндов

```c
// Значения по умолчанию
int Areg = 0, Breg = 0;
Operand Cop; 
Cop.type = OP_REG; 
Cop.value = 0;

// Парсинг A (если не указан, остаётся 0)
if (tA) {
    if (parse_reg(tA, &Areg) != 0) { ERROR; }
}

// Аналогично для B

// Для C (если не указан, = R0)
if (!tC) {
    Cop.type = OP_REG;
    Cop.value = 0;
}
```

## 3.3 Автопреобразования и предобработка

### 3.3.1 Удаление завершающих символов

Ассемблер автоматически удаляет символы конца строки:

```c
// Удаление '\n'
char *nl = strchr(p, '\n');
if (nl) *nl = '\0';
```

### 3.3.2 Обрезка начальных пробелов

Пробелы в начале строки игнорируются, позволяя использовать отступы для улучшения читаемости:

```assembly
    ADD R0, R1, R2        ; отступ для визуальной группировки
    SUB R3, R4, R5
        MUL R6, R7, R8    ; вложенный блок
```

```c
// Пропуск начальных пробелов
while (*p && isspace((unsigned char)*p)) p++;
```

### 3.3.3 Преобразование HALT → EXIT 0

Основное автопреобразование ассемблера (см. раздел 3.4):

```c
if (!raw_halt && strcasecmp(tok, "halt") == 0) {
    tok = "exit";
}
```

**Эффект:** Программист может писать `HALT` для удобства, но на уровне байткода это будет `EXIT` с кодом возврата 0.

### Таблица 3.3.4: Примеры лексического анализа

| Исходная строка           | После обработки         | Комментарий                     |
| ------------------------- | ----------------------- | ------------------------------- |
| `ADD R0, R1, R2`          | `ADD R0 R1 R2`          | Обрезка пробелов                |
| `SUB R3,R4,#10 ; comment` | `SUB R3 R4 #10`         | Удаление комментария            |
| `# Full line comment`     | (пропущена)             | Строка-комментарий              |
| (пустая строка)           | (пропущена)             | Игнорируется                    |
| `HALT`                    | `EXIT` (без --raw-halt) | Автопреобразование              |
| `MuL r10, R5, #2`         | `MUL R10 R5 #2`         | Регистронезависимость мнемоники |

# 5. Синтаксис операндов

## 5.1 Регистры

Регистры обозначаются префиксом `R` (обязательно в верхнем регистре) с последующим номером в десятичной или шестнадцатеричной нотации.

### 5.1.1 Десятичная нотация

```assembly
R0, R1, R2, ..., R255
```

**Примеры:**

```assembly
ADD R10, R5, R3       ; регистры 10, 5, 3
MUL R0, R1, R2        ; регистры 0, 1, 2
SUB R255, R100, R50   ; максимальный номер регистра
```

### 5.1.2 Шестнадцатеричная нотация

Префикс `0x` или `0X` указывает на шестнадцатеричное число:

```assembly
R0x00, R0x01, R0x0A, R0xFF
```

**Примеры:**

```assembly
AND R0x10, R0x20, R0xFF   ; регистры 16, 32, 255
OR  R0xA, R0xB, R0xC      ; регистры 10, 11, 12
```

### 5.1.3 Парсер регистров

```c
static int parse_reg(const char *tok, int *out_reg) {
    if (!tok || !*tok) return -1;
    if (tolower((unsigned char)tok[0]) != 'r') return -1;
    
    char *end;
    errno = 0;
    long v = strtol(tok+1, &end, 0);  // base=0: автоопределение (dec/hex)
    if (end == tok+1) return -1;       // нет цифр после 'R'
    if (errno) return -1;               // переполнение/ошибка
    
    *out_reg = (int)v;
    return 0;
}
```

**Особенности `strtol(..., 0)`:**

- `base=0` автоматически определяет основание:
    - `R123` → десятичное 123
    - `R0x7F` → шестнадцатеричное 127
    - `R0377` → восьмеричное (255) — **не рекомендуется**

### 5.1.4 Проверка диапазона

```c
static int check_reg_range(int r) {
    return (r >= 0 && r <= 0xFF);  // 0-255
}
```

**Ошибка при выходе за диапазон:**

```
Line 25: A out of range (0..255): 300
```

### Таблица 5.1: Примеры синтаксиса регистров

|Запись|Интерпретация|Валидность|Комментарий|
|---|---|---|---|
|`R0`|Регистр 0|✓|Минимальный номер|
|`R255`|Регистр 255|✓|Максимальный номер|
|`R0xFF`|Регистр 255|✓|Hex-нотация|
|`R0x10`|Регистр 16|✓|Hex-нотация|
|`R10`|Регистр 10|✓|Decimal-нотация|
|`R256`|—|✗|Выход за диапазон|
|`R-1`|—|✗|Отрицательный номер|
|`R`|—|✗|Отсутствует номер|
|`10`|—|✗|Отсутствует префикс 'R'|
|`r10`|Регистр 10|✓|Нижний регистр допустим (tolower)|

## 5.2 Immediate-операнды

Immediate-операнды (непосредственные значения, константы) обозначаются префиксом `#` с последующим числом в десятичной или шестнадцатеричной нотации.
Immediate-операнды представляют собой **8-битные знаковые числа** в дополнительном коде.
### 5.2.1 Десятичная нотация

**Диапазон:** **−128 ≤ immediate ≤ +127**

```assembly
#0, #1, #100, #-50, #127, #-128
```

**Примеры:**

```assembly
ADD R0, R1, #10       ; R0 = R1 + 10
SUB R3, R7, #-50      ; R3 = R7 - (-50) = R7 + 50
AND R0, R1, #0x7F     ; битовая маска (127)
```

### 5.2.2 Шестнадцатеричная нотация

```assembly
#0x00, #0xFF, #0x80, #-0x10
```

**Примеры:**

```assembly
AND R0, R1, #0xFF     ; битовая маска младшего байта
OR  R2, R3, #0x80     ; установка старшего бита байта
XOR R4, R5, #0x0F     ; инверсия младших 4 бит
```

### 5.2.3 Парсер immediate

```c
static int parse_immediate(const char *tok, int *out_val) {
    if (!tok || !*tok) return -1;
    if (tok[0] != '#') return -1;
    
    char *end;
    errno = 0;
    long v = strtol(tok+1, &end, 0);  // base=0 для автоопределения
    if (end == tok+1) return -1;
    if (errno) return -1;
    
    *out_val = (int)v;
    return 0;
}
```

### 5.2.4 Проверка диапазона (9-битное знаковое)

```c
static int check_imm8_range(int v) {
    return (v >= -128 && v <= 127);
}
```

**Ошибка при выходе за диапазон:**
```
Line 30: Immediate out of range for 8-bit signed (-128..127): 200
```


### Таблица 5.2: Примеры синтаксиса immediate

| Запись   | Значение | Валидность | Комментарий                |
| -------- | -------- | ---------- | -------------------------- |
| `#0`     | 0        | ✓          | Ноль                       |
| `#100`   | 100      | ✓          | Положительное decimal      |
| `#-50`   | -50      | ✓          | Отрицательное decimal      |
| `#127`   | 127      | ✓          | Максимальное положительное |
| `#-128`  | -128     | ✓          | Максимальное отрицательное |
| `#0x7F`  | 127      | ✓          | Hex-нотация                |
| `#-0x10` | -16      | ✓          | Отрицательное hex          |
| `#128`   | —        | ✗          | Выход за диапазон (>127)   |
| `#-129`  | —        | ✗          | Выход за диапазон (<-128)  |
| `#255`   | —        | ✗          | Выход за диапазон          |
| `#-256`  | —        | ✗          | Выход за диапазон          |

### 5.2.5 Представление отрицательных значений

Отрицательные immediate-значения кодируются в дополнительном коде в 9 битах:

```c
// Для значения v в диапазоне -256..+255
uint32_t u = (uint32_t)(v & 0xFF);  // младшие 8 бит
```

**Примеры:**

|Десятичное|Двоичное (8 бит)|Hex|В поле C|IMM бит|
|---|---|---|---|---|
|0|00000000|0x00|0x00|1 (если immediate)|
|1|00000001|0x01|0x01|1|
|127|01111111|0x7F|0x7F|1|
|-1|11111111|0xFF|0xFF|1|
|-10|11110110|0xF6|0xF6|1|
|-128|10000000|0x80|0x80|1|

## 5.3 Различие для полей A/B/C

### 5.3.1 Операнды A и B: только регистры

Поля A и B **всегда содержат номера регистров**. Immediate-операнды для A и B не поддерживаются:

```assembly
; ✓ Корректно:
ADD R10, R5, R3
MUL R0, R1, #2

; ✗ ОШИБКА:
ADD #10, R5, R3       ; ERROR: A должен быть регистром
SUB R10, #5, R3       ; ERROR: B должен быть регистром
```

**Обработка в ассемблере:**

```c
// Парсинг A — обязательно регистр
if (tA) {
    if (parse_reg(tA, &Areg) != 0) {
        fprintf(stderr, "Line %lu: bad operand A '%s' — expected R<n>\n",
                lineno, tA);
        return ERROR;
    }
}

// Аналогично для B
```

### 5.3.2 Операнд C: регистр или immediate

Поле C может содержать либо номер регистра, либо immediate-значение, в зависимости от политики opcode (cflags):

**1. Операции, допускающие immediate (`CFLAG_ALLOW_IMM`):**

```assembly
ADD R0, R1, R2        ; регистровый режим
ADD R0, R1, #10       ; immediate-режим
```

**2. Операции, требующие регистр (`CFLAG_C_MUST_REG`):**

```assembly
CONCAT R0, R1, R2     ; корректно
CONCAT R0, R1, #100   ; ОШИБКА: immediate недопустим
```

**3. Операции, не использующие C (`CFLAG_NONE`):**

```assembly
NOT R0, R1            ; C игнорируется (по умолчанию = R0)
SQRT R2, R5           ; C не имеет значения
```

### Таблица 5.3: Допустимые типы операндов по полям

|Поле|Допустимые типы|Проверка|Значение по умолчанию|
|---|---|---|---|
|A|Только регистр|`parse_reg()`|R0|
|B|Только регистр|`parse_reg()`|R0|
|C|Регистр или imm|`parse_reg()` или `parse_immediate()`|R0 или #0|

### 5.3.3 Алгоритм парсинга операнда C

```c
if (tC) {
    int r, immv;
    
    // Сначала пробуем распарсить как регистр
    if (parse_reg(tC, &r) == 0) {
        if (!check_reg_range(r)) { ERROR; }
        Cop.type = OP_REG;
        Cop.value = r;
    }
    // Затем пробуем распарсить как immediate
    else if (parse_immediate(tC, &immv) == 0) {
        // Проверяем, разрешён ли immediate для этого opcode
        if (!(opent->cflags & CFLAG_ALLOW_IMM)) {
            fprintf(stderr, "Opcode '%s' does not allow immediate\n", ...);
            return ERROR;
        }
        if (!check_imm9_range(immv)) { ERROR; }
        Cop.type = OP_IMM;
        Cop.value = immv;
    }
    // Не удалось распарсить ни как регистр, ни как immediate
    else {
        fprintf(stderr, "bad operand C '%s' — expected R<n> or #<imm>\n", tC);
        return ERROR;
    }
} else {
    // Операнд C не указан — используем значение по умолчанию
    Cop.type = OP_REG;
    Cop.value = 0;
}
```

### 5.3.4 Приоритет парсинга

Парсер пытается интерпретировать операнд C в следующем порядке:

1. **Регистр** (`R<num>`)
2. **Immediate** (`#<num>`)
3. **Ошибка** (некорректный синтаксис)

Это означает, что если операнд начинается с `R`, он будет интерпретирован как регистр, даже если за ним следует `#`.

**Примеры:**

```assembly
ADD R0, R1, R2        ; C = регистр 2
ADD R0, R1, #10       ; C = immediate 10
ADD R0, R1, 100       ; ОШИБКА: нет префикса
ADD R0, R1, R#10      ; ОШИБКА: некорректный синтаксис регистра
```

# 6. Семантика поля C и immediate-режима

## 6.1 Флаг IMM (бит 8)

Бит 8 в 32-битной инструкции определяет режим интерпретации поля C (биты 7-0):

```
┌───┬─────────┐
│ I │   C     │
│ 1 │  8 бит  │
└───┴─────────┘
  8    7..0
```

**Значения флага IMM:**

- `IMM = 0` → C содержит номер регистра (0-255)
- `IMM = 1` → C содержит знаковую константу (-256..+255)

### 6.1.1 Установка флага IMM в ассемблере

```c
if (Cop.type == OP_REG) {
    Cfield = (uint32_t)(Cop.value & 0xFF);
    // Бит 8 автоматически = 0 (регистровый режим)
}
else {  // OP_IMM
    int v = Cop.value;
    uint32_t u = (uint32_t)(v & 0x1FF);  // 9 бит (IMM + значение)
    Cfield = u;
    // Бит 8 в составе u будет = 1 для immediate
}
```

### 6.1.2 Чтение флага IMM в VM

```c
#define FIMM(instr) (((instr) >> 8) & 0x1)
#define SEXTIMM8(instr) sext(((instr) & 0xFF), 8)

// Использование в операциях:
uint32_t Cv_or_imm(uint32_t i) {
    return FIMM(i) ? SEXTIMM8(i) : reg[RC(i)];
}
```

## 6.2 Кодирование immediate

Immediate-значения кодируются как **8-битные знаковые числа** в дополнительном коде.

### 6.2.1 Диапазон значений

**Минимальное значение:** -128 
**Максимальное значение:** +127 

### 6.2.2 Формула кодирования

```c
// Входное значение: int v (в диапазоне -128..+127)
uint8_t c_field = (uint8_t)(v & 0xFF);
uint32_t imm_bit = 1;  // устанавливается отдельно

// Итоговое поле C в инструкции (биты 8..0):
uint32_t c_with_imm = (imm_bit << 8) | c_field;
```

### Таблица 6.1: Примеры кодирования immediate

| Decimal | Binary (8-bit) | Hex  | C field | IMM bit |
| ------- | -------------- | ---- | ------- | ------- |
| 0       | 00000000       | 0x00 | 0x00    | 1       |
| 1       | 00000001       | 0x01 | 0x01    | 1       |
| 127     | 01111111       | 0x7F | 0x7F    | 1       |
| -1      | 11111111       | 0xFF | 0xFF    | 1       |
| -10     | 11110110       | 0xF6 | 0xF6    | 1       |
| -128    | 10000000       | 0x80 | 0x80    | 1       |

**Важно:** Обратите внимание, что поле C (биты 7-0) для значений 0 и -256 одинаково (0x00), но отличается флаг IMM (бит 8).

### 6.2.3 Упаковка в инструкцию

```c
// Полная 32-битная инструкция:
uint32_t word = ((uint32_t)opcode << 25) |
                (Afield << 17) |
                (Bfield << 9) |
                Cfield;

// Где для immediate:
// Cfield включает:
//   - бит 8: IMM flag = 1
//   - биты 7-0: знаковое значение в дополнительном коде
```

**Пример: ADD R10, R5, #-10**

```
opcode = 0 (ADD)
A = 10 (0x0A)
B = 5 (0x05)
C = -10 → кодируется как 0x1F6 (9 бит)

Cfield = 0x1F6
  - бит 8 = 1 (IMM)
  - биты 7-0 = 0xF6 (-10 в дополнительном коде)

word = (0 << 25) | (10 << 17) | (5 << 9) | 0x1F6
     = 0x00000000 | 0x00140000 | 0x00000A00 | 0x000001F6
     = 0x00140BF6
```

## 6.3 Знаковое расширение при декодировании

При выполнении инструкции с immediate-операндом необходимо восстановить 32-битное знаковое значение из 8-битного поля C.

### 6.3.1 Макрос IMM8

```c
// Функция знакового расширения из funcs.h
static inline int32_t sext(uint32_t val, int bits) {
    int32_t m = 1U << (bits - 1);
    return (val ^ m) - m;
}

#define SEXTIMM8(instr) sext(((instr) & 0xFF), 8)
```

**Принцип работы:**

1. `(instr) & 0xFF` — извлекаем младший байт (биты 7-0)
2. `^ 0x80` — инвертируем бит 7 (бит знака)
3. `- 0x80` — выполняем коррекцию для получения правильного знака
4. `(int32_t)` — приведение к знаковому 32-битному типу

# 7. Правила валидации в ассемблере

Надёжность ассемблера во многом определяется качеством валидаций. Ниже — набор обязательных проверок, формат сообщений об ошибках и примеры.

## 7.1 Список обязательных проверок

1. **Диапазоны:**
    
    - `opcode` в 0..127 (7 бит)
        
    - `A`, `B` — регистры в 0..255
        
    - `C` как регистр — 0..255
        
    - `C` как immediate — −256..+255
        
2. **Политика cflags:**
    
    - если `CFLAG_C_MUST_REG` — запретить immediate
        
    - если `CFLAG_ALLOW_IMM` отсутствует — запретить immediate
        
3. **Синтаксис:**
    
    - правильные префиксы: `R` для регистров, `#` для immediate
        
    - пустые/лишние токены — ошибка
        
4. **Специальные проверки:**
    
    - для `TON/TOF/TP/CTU/CTD/CTUD` — проверка допустимых ID таймеров/счётчиков (напр., 0..15)
        
    - string ops — проверка указателей/границ (по возможности на этапе компоновки)
        
    - `JMP` с immediate — проверка выравнивания адреса (если требуются выравнивания)
        

## 7.2 Формат сообщений об ошибках

Рекомендуемый формат:

```
Line <lineno>: <file>:<lineno>: error: <описание>
Line <lineno>: <file>:<lineno>: note: <подсказка>
```

Примеры:

```
Line 42: program.asm:42: error: bad operand A '10' — expected R<n>
Line 30: program.asm:30: error: Immediate out of range for 9-bit signed (-256..255): 1000
Line 25: program.asm:25: error: Opcode 'CONCAT' requires C to be a register
```

## 7.3 Поведение при ошибках

- Ассемблер должен прерывать ассемблирование при первой фатальной ошибке.
    
- Для нефатальных предупреждений (например, потенциальный конфликт имён меток) — вывести `warning` и продолжать.
    
- При наличии ошибок — не выпускать бинарный файл.
    

# 8. Специальные семантики инструкций (дополнения и детали реализации)

В этом разделе даются дополнительные детали реализации и рекомендации поведения VM для категорий инструкций, перечисленных ранее.

## 8.1 Арифметика и логика — поведение на границах

- **Переполнение:** все арифметические операции производятся в `uint32_t` (или `int32_t` для знаковых операций), результат усечён до 32 бит. Специальные инструкции (например, `ADD_OVF`) отсутствуют — если нужен контроль переполнения, пользователь должен проверять флаги вручную.
    
- **DIV/MOD:** при делении на ноль результат должен быть 0 (без бросания исключения). Для диагностических сборок можно логировать предупреждение.
    
- **EXPT / трансцендентные функции:** используют плавающую арифметику; результат приводится к `uint32_t` по усечению/округлению (зависит от выбранной реализации — документируйте).
    

## 8.2 Сравнения

- Всегда записывают 0 или 1 в регистр A.
    
- Для unsigned/signed различий — инструкции предполагают unsigned сравнение, если не указано иное (в спецификации можно добавить `GT_S`/`GT_U` при потребности).
    

## 8.3 Строковые операции — безопасность и копирование

- **Память:** VM должна предоставлять функции `safe_strlen`, `safe_memcpy`, `safe_memmove`, которые проверяют границы буфера.
    
- **In-place vs copy-on-write:** `CONCAT` и подобные операции по умолчанию делают попытку in-place (если в памяти достаточно места), иначе — выделяют временный буфер и выполняют копию. Ассемблер/байткод должен передавать только адреса; управление памятью остаётся за рантаймом.
    
- **Ограничения:** операции на строках должны возвращать код ошибки (в регистр A или в глобальную диагонтику) при выходе за пределы памяти.
    

## 8.4 Таймеры и счётчики — хранение состояния

- **ID таймеров/счётчиков:** ограничьте число аппаратных/логических таймеров (например, 0..15). Состояние хранится во внутренних таблицах VM (preset, накопленное время, last_input_state).
    
- **Детектирование фронтов:** сравнивать последнее состояние входа и текущее. Увеличение / уменьшение счётчика — в момент положительного фронта.
    
- **Сброс при инициализации:** выполнение `TON`/`CTU` первой командой должно корректно инициализировать состояние таймера/счётчика.
    

## 8.5 Работа с памятью (mr32, safe_*)

- **Адреса и выравнивание:** операции чтения/записи 32-битных слов должны требовать выравнивания по 4 байта, или VM должна корректно собирать/разбирать слова на невыравненных адресах (производительность vs простота).
    
- **Границы:** проверять, чтобы `addr >= 0 && addr + 3 < MEM_BYTES`.
    
- **Возврат ошибок:** при выходе за границы возвращать 0 и, возможно, выставлять флаг ошибки.
    

## 8.6 Выбор/мультиплексирование (SEL/MUX)

- `SEL`: берёт базовый адрес в R2 и условие в R1; выбирает одно из двух подряд идущих 32-бит слов: `mem[base + (cond ? 0 : 4)]`.
    
- `MUX`: индекс в C; адрес = `B + C*4`; проверять выход за границы.

# 9. Управление потоком (адреса переходов, FIMM и детали)

## 9.1 Формирование адреса для JMP

Переходы допускают два режима задания адреса:

1. **Регистровый:** адрес берётся из регистра B (или A в зависимости от мнемоники). Пример: `JMP R5` — PC := regs[5].
    
2. **Immediate (FIMM):** адрес содержится как непосредственная константа в поле C (FIMM=1). Пример: `JMP #0x3100`.
    

**Рекомендации:**

- Нумерация адресов — в инструкциях байткода указывать абсолютный адрес инструкции (см. формат выходного файла). Если вы используете метки, ассемблер разрешает относительную адресацию и вычисляет абсолютный адрес на этапе сборки.
    
- Если VM использует выровненные адреса инструкций (по 4 байта), проверяйте, что адрес делится на 4 (иначе — предупреждение/ошибка).
    

## 9.2 FIMM (Full Immediate) — примечания

- FIMM — тот же флаг IMM, применённый в инструкции перехода: отличает ли поле C immediate-адрес или индекс регистра.
    
- При использовании immediate-адресов убедитесь, что assembler/сборщик позволяет закодировать 9-битное значение как часть полного 32-битного адреса (часто immediate нужен как смещение или часть большего выражения). Если требуются 32-битные адреса — предусмотреть последовательность инструкций `LDHI/LDLO` или специальную инструкцию загрузки константы.
    

## 9.3 Условные переходы — откуда берётся условие

- `JMP_IF A, addr, C` — традиционно: условие берётся из регистра A (или из результата предыдущей операции, записанного в A). Реализация в VM: если `regs[A] != 0` → выполнить переход.
    
- В вашем наборе вы использовали переводное правило: иногда условие записывается в регистр A инструкцией сравнения, затем `JMP_IF Rcond, addr, R?` — соглашение должно быть чётким в спецификации.
    
- `JMP_IF_NOT` — обратное поведение: выполняется, если `regs[A] == 0`.
    

## 9.4 EXIT и HALT (поведенческие уточнения)

- `EXIT`: если `A == 0` → код выхода = immediate (C), иначе код выхода = regs[A]. VM должен корректно установить `vm_exit_code`.
    
- `HALT` (raw): немедленная остановка — не устанавливает код выхода. В нормальном режиме (`--raw-halt` не указан) ассемблер должен трансформировать `HALT` в `EXIT 0`.

# 10. Бинарный формат и layout выходного файла — практические рекомендации

## 10.1 Формат бинарника

- Байткод = последовательность инструкций по 4 байта в **little-endian**.
    
- Никакого внутреннего выравнивания между инструкциями не требуется — фиксированная длина 4 байта упрощает это.
    

## 10.2 Рекомендуемый минимальный заголовок (опционально)

Если нужен расширяемый формат образа, добавьте небольшой заголовок:

```c
struct vm32_header {
    uint32_t magic;      // например, 0x564D3332 'VM32'
    uint16_t version;    // версия формата, e.g. 1
    uint16_t flags;      // флаги (например, has_debug)
    uint32_t entry;      // адрес точки входа (в байтах)
    uint32_t code_size;  // размер секции кода в байтах
    uint32_t data_size;  // размер секции данных
    // далее опционально: debug info, symbols...
};
```

**Плюсы заголовка:** позволяет хранить метаданные, версионирование, отладочную информацию. **Минус:** усложняет простой `asm2bin` — сделайте это опцией (`--with-header`).

## 10.3 Опция `--raw-halt`

- Влияет только на то, как ассемблер трактует `HALT`. Не меняет формат бинарного файла.
    
- Если `--raw-halt` не указан — при сборке `HALT` трансформируется в `EXIT 0`.
    

## 10.4 Debug/символы

- Для поддержки дизассемблирования добавляйте (опционально) таблицу символов: `offset -> source line / label name`.
    
- При необходимости храните простую карту меток: облегчает отладку, не увеличивает сильно размер.

# 11. Примеры и образцы кода

Ниже — набор коротких примеров, служащих шаблонами.

## 11.1 NOP / HALT / EXIT

```assembly
; NOP example
NOP

; HALT (ассемблер по умолчанию преобразует в EXIT 0)
HALT

; EXIT с кодом 42
EXIT R0, R0, #42
```

## 11.2 Простая арифметика

```assembly
; R0 = (R1 + 5) * (R2 - 3)
ADD R3, R1, #5
SUB R4, R2, #3
MUL R0, R3, R4
```

## 11.3 Условный цикл (псевдокод на VM32)

```assembly
; i = 0
; while (i < 10) { i = i + 1; }
ADD R0, R0, #0        ; R0 = 0 (обнуляем)
.loop:
LT R2, R0, #10        ; R2 = (R0 < 10) ? 1 : 0
JMP_IF_NOT R0, #.end, R2  ; если R2=0 (условие из C!), выход
ADD R0, R0, #1        ; i++
JMP #.loop            ; повторить
.end:
NOP
```

(Примечание: если нет `MOV`, используйте `ADD R0, R0, #0` как загрузку из регистра R0; в реальном наборе стоит добавить явную `MOV`/`LDI` инструкцию.)

## 11.4 Строковая операция (конкатенация)

```assembly
; Конкатенировать string at R2 в string at R1, результат в R1
CONCAT R1, R1, R2
```
