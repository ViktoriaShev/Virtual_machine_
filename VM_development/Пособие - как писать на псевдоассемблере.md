Система машинных команд является важнейшей частью архитектуры виртуальной машины VM32, так как с их помощью производится непосредственное управление работой интерпретатора. В отличие от реальных процессоров, таких как Intel Pentium (содержащих более 300 команд), VM32 спроектирована с акцентом на простоту и единообразие форматов.

При знакомстве с системой машинных команд VM32 необходимо учитывать два аспекта — собственно набор машинных команд и правила представления этих команд на уровне интерпретатора, то есть формат машинных команд. Виртуальной машине понятен только один формат — 32-битные инструкции фиксированной длины. Машинные команды представляют собой сформированные по определенным правилам последовательности битов.

Для облегчения процесса разработки программ был создан ассемблер VM32, как символический аналог машинного языка. Существует взаимно однозначное соответствие машинных команд и команд ассемблера. Понимание правил формирования машинных команд из команд ассемблера является одним из необходимых условий не только для изучения языка ассемблера VM32, но и для понимания логики работы виртуальной машины в целом.

## Общая структура инструкции

Все инструкции в VM32 имеют **фиксированный размер 32 бита** (4 байта) и следуют единому формату кодирования. Фиксированная длина упрощает декодирование и позволяет эффективно использовать память.

### Формат инструкции

Каждая инструкция занимает ровно **32 бита**:

![[Форма команды.drawio.png]]


**Поля инструкции:**

- **Opcode** (биты 31–25, 7 бит) — код операции, определяющий выполняемое действие (диапазон 0–127)
- **A** (биты 24–17, 8 бит) — регистр назначения, куда записывается результат операции (диапазон 0–255)
- **B** (биты 16–9, 8 бит) — первый операнд-источник, всегда регистр (диапазон 0–255)
- **IMM** (бит 8, 1 бит) — флаг режима immediate: 0 = регистр C, 1 = непосредственное значение
- **C/IMM** (биты 7–0, 8 бит) — второй операнд: регистр или знаковая константа

**Immediate-режим**: Бит 8 определяет интерпретацию поля C:

- `IMM=0` → C содержит индекс регистра (0–255)
- `IMM=1` → C содержит знаковую константу в диапазоне -256..+255 с автоматическим расширением знака до 32 бит

## Побитовое представление инструкции

### Формирование машинного кода

При формировании 32-битного слова инструкции используется следующая упаковка полей (порядок байтов — little-endian):

```c
uint32_t word = ((uint32_t)op << 25) | 
                (Afield << 17) | 
                (Bfield << 9) | 
                Cfield;
```

Где компоненты вычисляются следующим образом:

**Поле опкода:**

```c
uint32_t op = opcode & 0x7F;  // 7 бит (0-127)
if (op < 0 || op > 0x7F) {
    fprintf(stderr, "Opcode code out of range\n");
    return ERROR;
}
```

**Поля регистров A и B:**

```c
uint32_t Afield = (uint32_t)(Areg & 0xFF);  // 8 бит (0-255)
uint32_t Bfield = (uint32_t)(Breg & 0xFF);  // 8 бит (0-255)
```

**Поле C (зависит от типа операнда):**

- **Регистровый режим** (IMM=0):
    
    ```c
    if (Cop.type == OP_REG) {
        Cfield = (uint32_t)(Cop.value & 0xFF);  // биты 7-0: номер регистра
        // бит 8 автоматически = 0
    }
    ```
    
- **Immediate-режим** (IMM=1):
    
    ```c
    if (Cop.type == OP_IMM) {
        // Знаковое значение в дополнительном коде
        int v = Cop.value;
        uint32_t u = (uint32_t)(v & 0x1FF);  // младшие 9 бит (включая IMM)
        Cfield = u;
    }
    ```
    

### Запись в память

Результирующее 32-битное слово записывается в память побайтово в порядке little-endian (младший байт по младшему адресу):

```c
uint8_t bytes[4];
bytes[0] = (uint8_t)(word & 0xFF);           // биты 7-0
bytes[1] = (uint8_t)((word >> 8) & 0xFF);    // биты 15-8
bytes[2] = (uint8_t)((word >> 16) & 0xFF);   // биты 23-16
bytes[3] = (uint8_t)((word >> 24) & 0xFF);   // биты 31-24

if (fwrite(bytes, 1, 4, out) != 4) {
    perror("fwrite");
    return ERROR;
}
```

**Пример записи:**

Для инструкции с word = `0x12345678`:

```
Адрес    Байт    Описание
------   ----    ---------
0x3000   0x78    младший байт (биты 7-0)
0x3001   0x56    биты 15-8
0x3002   0x34    биты 23-16
0x3003   0x12    старший байт (биты 31-24)
```

## Декодирование инструкции

При чтении инструкции из памяти выполняется обратная операция — извлечение полей из 32-битного слова с помощью битовых масок и сдвигов.

### Макросы декодирования

В файле `vm32.h` определены следующие макросы для извлечения полей:

```c
// Чтение 32-битного слова из памяти (little-endian)
#define mr32(addr) \
    ((uint32_t)mem[addr] | \
     ((uint32_t)mem[addr+1] << 8) | \
     ((uint32_t)mem[addr+2] << 16) | \
     ((uint32_t)mem[addr+3] << 24))

// Извлечение полей инструкции
#define OPC(instr)  (((instr) >> 25) & 0x7F)    // биты 31-25: opcode (7 бит)
#define RA(instr)   (((instr) >> 17) & 0xFF)    // биты 24-17: регистр A (8 бит)
#define RB(instr)   (((instr) >> 9) & 0xFF)     // биты 16-9:  регистр B (8 бит)
#define FIMM(instr) (((instr) >> 8) & 0x1)      // бит 8:      флаг IMM (1 бит)
#define RC(instr)   ((instr) & 0xFF)            // биты 7-0:   регистр C (8 бит)
```

### Знаковое расширение immediate-операнда

Для immediate-операндов выполняется знаковое расширение из 8 бит в 32 бита:

```c
#define IMM8(instr) \
    ((int32_t)((((instr) & 0xFF) ^ 0x80) - 0x80))
```

Эта формула работает следующим образом:

- `(instr) & 0xFF` — извлекает младший байт (биты 7-0)
- `^ 0x80` — инвертирует бит знака
- `- 0x80` — выполняет коррекцию для получения правильного знакового значения

**Альтернативная реализация с явным ветвлением:**

```c
int32_t immediate;
uint8_t C_field = (uint8_t)(instr & 0xFF);

if (C_field & 0x80) {
    // Старший бит установлен — отрицательное число
    immediate = (int32_t)(C_field | 0xFFFFFF00);
} else {
    // Старший бит сброшен — положительное число
    immediate = (int32_t)C_field;
}
```

### Структура декодированной инструкции

Для оптимизации многократного декодирования используется кеширование:

```c
typedef struct {
    uint32_t raw_instr;      // исходное 32-битное слово
    uint8_t opcode;          // код операции (0-127)
    uint8_t ra;              // регистр A (0-255)
    uint8_t rb;              // регистр B (0-255)
    uint8_t rc;              // регистр C (0-255)
    bool has_immediate;      // флаг immediate-режима
    int32_t immediate;       // значение immediate (со знаковым расширением)
} decoded_instr_t;
```

### Процесс декодирования с кешированием

```c
static decoded_instr_t *decode_instruction(uint32_t addr) {
    // Проверяем кеш
    uint32_t key = addr;
    decoded_instr_t *cached = hash_table_lookup(decoded_cache, &key);
    if (cached) return cached;

    // Безопасная проверка границ памяти
    if (addr >= MEM_BYTES - 3) return NULL;

    // Чтение инструкции из памяти
    uint32_t instr = mr32(addr);

    // Выделение и заполнение структуры
    decoded_instr_t *dec = malloc(sizeof(decoded_instr_t));
    if (!dec) {
        fprintf(stderr, "decode_instruction: malloc failed\n");
        return NULL;
    }

    dec->raw_instr = instr;
    dec->opcode = OPC(instr);
    dec->ra = RA(instr);
    dec->rb = RB(instr);
    dec->rc = RC(instr);
    dec->has_immediate = FIMM(instr);
    dec->immediate = dec->has_immediate ? IMM8(instr) : 0;

    // Сохранение в кеш
    hash_table_insert(decoded_cache, &key, dec);

    return dec;
}
```

**Преимущества кеширования:**

- Декодирование выполняется только один раз для каждого адреса
- Повторное обращение к той же инструкции возвращает готовую структуру
- Критично для циклических участков кода

## Примеры инструкций в памяти

### Пример 1: Регистровая операция

**Ассемблер:**

```assembly
ADD R10, R5, R3
```

**Кодирование (предположим, ADD = opcode 0):**

- Opcode = 0
- A = 10 (0x0A)
- B = 5 (0x05)
- IMM = 0 (регистровый режим)
- C = 3 (0x03)

**Формирование слова:**

```c
word = (0 << 25) | (10 << 17) | (5 << 9) | 3
     = 0x00000000 | 0x00140000 | 0x00000A00 | 0x00000003
     = 0x00140A03
```

**Байты в памяти (little-endian):**

```
Адрес    Байт    Двоичное представление
------   ----    ----------------------
0x3000   0x03    00000011  (C=3)
0x3001   0x0A    00001010  (B=5, IMM=0)
0x3002   0x14    00010100  (A=10, часть)
0x3003   0x00    00000000  (Opcode=0)
```

**Декодирование:**

```c
uint32_t instr = mr32(0x3000);  // = 0x00140A03

uint8_t opcode = OPC(instr);    // = (0x00140A03 >> 25) & 0x7F = 0
uint8_t ra = RA(instr);         // = (0x00140A03 >> 17) & 0xFF = 10
uint8_t rb = RB(instr);         // = (0x00140A03 >> 9) & 0xFF = 5
bool imm = FIMM(instr);         // = (0x00140A03 >> 8) & 0x1 = 0
uint8_t rc = RC(instr);         // = 0x00140A03 & 0xFF = 3

// Результат: ADD R10, R5, R3
```

### Пример 2: Immediate-операция (положительное значение)

**Ассемблер:**

```assembly
ADD R10, R5, #100
```

**Кодирование:**

- Opcode = 0 (ADD)
- A = 10 (0x0A)
- B = 5 (0x05)
- IMM = 1
- C = 100 (0x64)

**Формирование слова:**

```c
// Immediate = 100 в 9 битах
Cfield = 100 & 0x1FF = 0x164  // бит 8 установлен (IMM=1)

word = (0 << 25) | (10 << 17) | (5 << 9) | 0x164
     = 0x00140B64
```

**Байты в памяти:**

```
Адрес    Байт    Двоичное представление
------   ----    ----------------------
0x3000   0x64    01100100  (C=100)
0x3001   0x0B    00001011  (B=5, IMM=1)
0x3002   0x14    00010100  (A=10, часть)
0x3003   0x00    00000000  (Opcode=0)
```

**Декодирование:**

```c
uint32_t instr = mr32(0x3000);  // = 0x00140B64

bool imm = FIMM(instr);         // = 1
int32_t immediate = IMM8(instr); // = 100

// Результат: ADD R10, R5, #100
```

### Пример 3: Immediate-операция (отрицательное значение)

**Ассемблер:**

```assembly
SUB R7, R2, #-10
```

**Кодирование (предположим, SUB = opcode 1):**

- Opcode = 1
- A = 7 (0x07)
- B = 2 (0x02)
- IMM = 1
- C = -10

**Представление -10 в дополнительном коде:**

```c
int v = -10;
uint32_t u = (uint32_t)(v & 0x1FF);  // = 0x1F6

// Побитовое представление:
// -10 в 32 битах = 0xFFFFFFF6
// Младшие 9 бит  = 0x1F6 (биты: 111110110)
// Бит 8 (IMM) = 1, биты 7-0 = 0xF6
```

**Формирование слова:**

```c
Cfield = 0x1F6;

word = (1 << 25) | (7 << 17) | (2 << 9) | 0x1F6
     = 0x020E05F6
```

**Байты в памяти:**

```
Адрес    Байт    Двоичное представление
------   ----    ----------------------
0x3004   0xF6    11110110  (C=-10 в доп. коде)
0x3005   0x05    00000101  (B=2, IMM=1)
0x3006   0x0E    00001110  (A=7, часть)
0x3007   0x02    00000010  (Opcode=1)
```

**Декодирование со знаковым расширением:**

```c
uint32_t instr = mr32(0x3004);  // = 0x020E05F6

uint8_t C_field = RC(instr);    // = 0xF6
bool imm = FIMM(instr);         // = 1

// Знаковое расширение:
if (C_field & 0x80) {  // 0xF6 & 0x80 = 0x80 (старший бит установлен)
    immediate = (int32_t)(C_field | 0xFFFFFF00);
    // = 0xFFFFFFF6 = -10 в десятичной системе
}

// Результат: SUB R7, R2, #-10
```

### Пример 4: Операция без второго операнда

**Ассемблер:**

```assembly
NOP
```

**Кодирование (предположим, NOP = opcode 63):**

- Opcode = 63 (0x3F)
- A = 0 (по умолчанию)
- B = 0 (по умолчанию)
- IMM = 0
- C = 0 (по умолчанию)

**Формирование слова:**

```c
word = (63 << 25) | (0 << 17) | (0 << 9) | 0
     = 0x7E000000
```

**Байты в памяти:**

```
Адрес    Байт    Описание
------   ----    --------
0x3008   0x00    все операнды = 0
0x3009   0x00
0x300A   0x00
0x300B   0x7E    opcode=63 (биты 31-25 = 0111111)
```

```c
static int check_reg_range(int r) {
    return (r >= 0 && r <= 0xFF);  // 0-255
}

static int check_imm9_range(int v) {
    return (v >= -256 && v <= 255);  // 9-битное знаковое
}

static int check_opcode_range(int op) {
    return (op >= 0 && op <= 0x7F);  // 0-127
}
```

## Синтаксис операндов в ассемблере

При написании программ на ассемблере VM32 используется следующий синтаксис:

### Регистры

Регистры обозначаются префиксом `R` с последующим десятичным или шестнадцатеричным номером:

```assembly
R0, R1, R2, ..., R255     ; десятичная нотация
R0x00, R0x01, R0xFF       ; шестнадцатеричная нотация
```

**Парсинг регистров в ассемблере:**

```c
static int parse_reg(const char *tok, int *out_reg) {
    if (!tok || !*tok) return -1;
    if (tolower((unsigned char)tok[0]) != 'r') return -1;
    
    char *end;
    errno = 0;
    long v = strtol(tok+1, &end, 0);  // base=0 позволяет 0x префикс
    if (end == tok+1) return -1;       // нет цифр после 'R'
    if (errno) return -1;               // переполнение
    
    *out_reg = (int)v;
    return 0;
}
```

**Примеры корректного синтаксиса:**

```assembly
ADD R10, R5, R3       ; регистры 10, 5, 3
MUL R0, R1, R2        ; регистры 0, 1, 2
SUB R255, R100, R50   ; максимальный номер регистра
```

**Примеры некорректного синтаксиса:**

```assembly
ADD 10, 5, 3          ; ERROR: отсутствует префикс 'R'
ADD R, R5, R3         ; ERROR: отсутствует номер регистра
ADD R-1, R5, R3       ; ERROR: отрицательный номер
ADD R256, R5, R3      ; ERROR: номер вне диапазона
```

### Непосредственные операнды (Immediate)

Константы обозначаются префиксом `#` с последующим десятичным или шестнадцатеричным числом:

```assembly
#число                ; десятичное представление
#0xчисло              ; шестнадцатеричное представление
```

**Парсинг immediate-операндов:**

```c
static int parse_immediate(const char *tok, int *out_val) {
    if (!tok || !*tok) return -1;
    if (tok[0] != '#') return -1;
    
    char *end;
    errno = 0;
    long v = strtol(tok+1, &end, 0);  // base=0 для hex поддержки
    if (end == tok+1) return -1;
    if (errno) return -1;
    
    *out_val = (int)v;
    return 0;
}
```

**Примеры корректного синтаксиса:**

```assembly
ADD R10, R5, #100     ; константа 100 (десятичная)
SUB R3, R7, #-50      ; константа -50
MUL R0, R1, #0x10     ; константа 16 (шестнадцатеричная)
AND R5, R5, #0xFF     ; битовая маска
```

**Примеры некорректного синтаксиса:**

```assembly
ADD R10, R5, 100      ; ERROR: отсутствует префикс '#'
ADD R10, R5, #        ; ERROR: отсутствует значение
ADD R10, R5, #500     ; ERROR: значение вне диапазона
ADD R10, R5, #-300    ; ERROR: значение вне диапазона
```

### Правила использования immediate-операндов

Не все инструкции поддерживают immediate-режим для операнда C. Каждая операция имеет флаги, определяющие допустимые типы операндов:

```c
typedef struct {
    const char *name;     // мнемоника команды
    int code;             // числовой код операции
    unsigned cflags;      // флаги для операнда C
} OpEntry;

// Флаги для операнда C:
#define CFLAG_ALLOW_IMM   0x01  // разрешен immediate
#define CFLAG_C_MUST_REG  0x02  // требуется регистр
```

**Проверка в ассемблере:**

```c
// Проверка разрешения immediate
if (Cop.type == OP_IMM && !(opent->cflags & CFLAG_ALLOW_IMM)) {
    fprintf(stderr, "Line %lu: Opcode '%s' does not allow immediate in C\n",
            lineno, opent->name);
    return ERROR;
}

// Проверка требования регистра
if ((opent->cflags & CFLAG_C_MUST_REG) && Cop.type == OP_IMM) {
    fprintf(stderr, "Line %lu: Opcode '%s' requires C to be a register\n",
            lineno, opent->name);
    return ERROR;
}
```

**Типичные категории операций:**

- **Допускают immediate:**
    
    ```assembly
    ADD R0, R1, #10       ; арифметика
    SUB R0, R1, #5
    MUL R0, R1, #2
    AND R0, R1, #0xFF     ; логика
    OR  R0, R1, #0x80
    EQ  R0, R1, #0        ; сравнения
    GT  R0, R1, #100
    ```
    
- **Требуют регистр:**
    
    ```assembly
    JMP R0, R1, R2        ; управление потоком
    LOAD R0, R1, R2       ; работа с памятью (возможно)
    ```
    

При запуске ассемблер выводит список операций, поддерживающих immediate:

```
Assembler: C immediate accepted for opcodes: ADD SUB M
```
