## Обзор

VM32 — специализированная 32-битная виртуальная машина, разработанная для выполнения программ промышленных программируемых логических контроллеров (ПЛК). Архитектура соответствует стандартам **IEC 61131-3** и обеспечивает полный набор функциональных блоков для промышленной автоматизации.

### Ключевые особенности

-  **Циклическая модель выполнения** — детерминированные циклы ПЛК с контролем времени
-  **Контроль целостности** — CRC32-хеширование состояния между циклами
-  **IEC 61131-3 совместимость** — стандартные таймеры (TON/TOF/TP) и счётчики (CTU/CTD/CTUD)
-  **64 МБ памяти** — линейное адресное пространство с побайтовой адресацией
-  **256 регистров** — 32-битные регистры общего назначения
-  **Immediate-операнды** — поддержка констант в инструкциях для оптимизации

## Архитектура

### Основные характеристики

| Параметр              | Значение                  |
| --------------------- | ------------------------- |
| **Разрядность**       | 32 бита                   |
| **Объём памяти**      | 64 МиБ (67 108 864 байта) |
| **Регистры**          | 256 × 32-битных           |
| **Формат инструкций** | Фиксированный, 32 бита    |
| **Порядок байтов**    | Little-Endian             |
| **Опкоды**            | 68  (расширяемо до 127)   |

### Формат инструкции

Каждая инструкция занимает ровно **32 бита**:

```
┌─────────┬─────────┬─────────┬───┬─────────┐
│ Opcode  │    A    │    B    │ I │   C/IMM │
│ 7 бит   │  8 бит  │  8 бит  │ 1 │  8 бит  │
└─────────┴─────────┴─────────┴───┴─────────┘
  31..25    24..17    16..9     8    7..0
```

**Поля:**

- **Opcode** (7 бит) — код операции (0–127)
- **A** (8 бит) — регистр назначения (результат)
- **B** (8 бит) — первый операнд (регистр)
- **IMM** (1 бит) — режим immediate: 0 = регистр C, 1 = константа
- **C** (8 бит) — второй операнд (регистр или signed immediate)

**Immediate-режим**: Бит 24 определяет, как интерпретировать поле C:

- `IMM=0` → C — индекс регистра (0–511)
- `IMM=1` → C — знаковая константа (-256..+255) с автоматическим расширением до 32 бит

## Модель выполнения

### Циклическая архитектура ПЛК
![[General_chart_of_vm.drawio.svg]]
VM32 работает в режиме **детерминированных циклов**, типичном для промышленных контроллеров:

```
╔═══════════════════════════════════════════════════════════╗
║  ЦИКЛ N                                                   ║
╠═══════════════════════════════════════════════════════════╣
║  1. Вычисление хеша регистров (начало цикла)             ║
║  2. Выполнение программы от PC_START до HALT/EXIT         ║
║  3. Обновление всех таймеров (TON/TOF/TP)                ║
║  4. Вычисление хеша регистров (конец цикла)              ║
║  5. Проверка целостности (сравнение с предыдущим циклом)  ║
║  6. Контроль времени выполнения (cycle_time_ms)          ║
║  7. Пауза до начала следующего цикла                      ║
╚═══════════════════════════════════════════════════════════╝
```

### Конфигурация VM

```c
typedef struct {
    uint32_t cycle_time_ms;      // Время цикла ПЛК (по умолчанию 1000 мс)
    uint32_t clock_rate_hz;      // Ограничение скорости (0 = без лимита)
    bool enable_cycle_check;     // Предупреждение о перерасходе времени
    bool enable_hash_check;      // CRC32-контроль между циклами
    bool enable_tick_timing;     // Точное ограничение тактовой частоты
    hash_algorithm_t hash_algo;  // HASH_CRC32 или HASH_SIMPLE_FNV1A
} vm_config_t;
```

**Пример настройки:**

```c
vm_config.cycle_time_ms = 100;        // Цикл 100 мс (10 Гц)
vm_config.enable_hash_check = true;   // Проверка целостности
vm_config.hash_algo = HASH_CRC32;     // CRC32 для надёжности
```

---
### Модель экземпляров

VM32 поддерживает **множественные изолированные экземпляры**. Каждый экземпляр `vm_state_t` содержит собственную память, регистры, таймеры и конфигурацию.

**Управление жизненным циклом:**
```c
// Создание нового экземпляра VM
vm_state_t *vm = vm_create();

// Инициализация настроек по умолчанию
vm_init_defaults(vm);

// Настройка конфигурации
vm->config.cycle_time_ms = 100;
vm->config.enable_hash_check = true;

// Загрузка программ
const char *programs[] = {"main.bin", "lib.bin"};
load_programs(vm, programs, 2);

// Выполнение
run_program(vm);

// Очистка
vm_destroy(vm);
```

**Преимущества инстансной модели:**
- Изоляция состояния между VM
- Потокобезопасное параллельное выполнение (с внешней синхронизацией)
-  Упрощённое тестирование
- Возможность запуска нескольких программ одновременно

### 5. IEC 61131-3 Таймеры

VM32 предоставляет **16 экземпляров** каждого типа таймера (ID: 0–15):

#### TON (Timer On-Delay) — Задержка включения

```
IN ──┐     ┌──────────── OUT
     │     │ (preset_ms)
     └─────┘
```

- При переходе `IN: 0→1` начинается отсчёт
- `OUT=1` когда `elapsed ≥ preset_ms`
- При `IN=0` выход немедленно сбрасывается

#### TOF (Timer Off-Delay) — Задержка выключения

```
IN ────────┐
           │ (preset_ms)
OUT ───────┴──────────
```

- Пока `IN=1` → `OUT=1`
- При `IN: 1→0` выход остаётся активным `preset_ms`

#### TP (Timer Pulse) — Генератор импульса

```
IN  ─┐
     │
OUT  └───────┐
     (fixed) │
             └─────
```

- Фронт `IN: 0→1` генерирует импульс длительностью `preset_ms`
- Повторные переходы игнорируются до завершения

**Использование:**

```assembly
; TON с ID=2, вход=R10, preset=R5(мс), результат→R1
TON R1, R10, R5      ; reg[1] = ton_Q(2)

; С immediate preset (500 мс)
TON R1, R10, #500
```

### 6. Счётчики

|Опкод|Тип|Описание|Immediate|
|---|---|---|---|
|50|**CTU**|Count Up|✅ preset|
|51|**CTD**|Count Down|✅ preset|
|52|**CTUD**|Up-Down|—|

**Пример:**

```assembly
CTU R3, R10, #100    ; Счёт до 100 (immediate preset)
```

### 7. Переходы (с immediate)

| Опкод | Инструкция                | Immediate |
| ----- | ------------------------- | --------- |
| 56    | **JMP** addr              | ✅         |
| 57    | **JMP_IF** cond, addr     | ✅ addr    |
| 58    | **JMP_IF_NOT** cond, addr | ✅ addr    |

**Примеры:**

```assembly
JMP #0x3100          ; Безусловный переход (immediate адрес)
JMP_IF R5, #0x3200   ; Если R5≠0, переход на 0x3200
JMP R10              ; Переход по адресу из регистра
```

| Опкод | Инструкция      | Описание                    |
| ----- | --------------- | --------------------------- |
| 59    | **EXIT** [code] | Завершение с кодом возврата |
| 60    | **HALT**        | Останов VM                  |
| 61    | **NOP**         | Нет операции                |

### 9. Детекторы фронтов и защёлки (IEC/SCADA)

VM32 предоставляет **16 экземпляров** каждого типа (ID: 0–15):

#### Детекторы фронтов
| Опкод | Инструкция       | Описание                         | Immediate |
| ----- | ---------------- | -------------------------------- | --------- |
| 62    | **RISING_EDGE**  | Детектор переднего фронта (0→1)  | ✅ ID      |
| 63    | **FALLING_EDGE** | Детектор заднего фронта (1 -> 0) | ✅ ID      |
| 64    | **EDGE_BOTH**    | Детектор любого изменения        | ✅ ID      |

**Использование:**

```assembly
; Детектор переднего фронта, ID=5 (immediate), вход=R10
RISING_EDGE R1, R10, #5      ; R1=1 только при 0→1

; Альтернатива без immediate (ID из регистра A)
RISING_EDGE R1, R10          ; ID берётся из R1 перед записью
```

**Логика работы:**

- Сохраняет предыдущее состояние входа для каждого ID
- `RISING_EDGE`: выход `1` только в цикле перехода `0→1`
- `FALLING_EDGE`: выход `1` только в цикле перехода `1→0`
- `EDGE_BOTH`: выход `1` при любом изменении входа

**Режим immediate:**

- Когда `IMM=1`: поле C содержит ID экземпляра (0–15)
- Когда `IMM=0`: ID берётся из `reg[A]` перед записью результата

#### Защёлки (Latches)

|Опкод|Тип|Приоритет|Immediate|
|---|---|---|---|
|65|**RS_LATCH**|Reset (R имеет приоритет)|✅ ID|
|66|**SR_LATCH**|Set (S имеет приоритет)|✅ ID|

**Таблицы истинности:**

```
RS_LATCH (Reset priority):
S R | Q
0 0 | сохранить
0 1 | 0
1 0 | 1
1 1 | 0  ← Reset приоритетнее

SR_LATCH (Set priority):
S R | Q
0 0 | сохранить
0 1 | 0
1 0 | 1
1 1 | 1  ← Set приоритетнее
```

**Примеры:**

```assembly
; RS-защёлка ID=3 (immediate), S=R7, R=R8
RS_LATCH R1, R7, R8, #3      ; R1 = текущее состояние Q

; SR-защёлка без immediate (ID из R1)
SR_LATCH R1, R7, R8          ; ID берётся из R1 перед записью
```

**Входы:**

- Регистр B содержит вход **S** (Set)
- Регистр C содержит вход **R** (Reset)
- Результат записывается в регистр A

**Режим immediate:**

- Когда `IMM=1`: поле C содержит ID экземпляра защёлки (0–15), входы S и R берутся из B и специального регистра
- Когда `IMM=0`: ID берётся из `reg[A]`, входы S из `reg[B]`, R из `reg[C]`

### 10. Демультиплексор

|Опкод|Операция|Описание|Immediate|
|---|---|---|---|
|67|**DEMUX**|Запись по индексу|✅ idx|

**Операция**: записывает значение из регистра A в ячейку массива

```
mem[baseAddr + idx*4] ← reg[A]
```

**Пример:**

```assembly
; Записать R5 в массив по адресу R10, индекс 7 (immediate)
DEMUX R5, R10, #7            ; mem[R10 + 7*4] = R5

; Индекс из регистра R3
DEMUX R5, R10, R3            ; mem[R10 + R3*4] = R5
```

**Применение**: маршрутизация данных, управление выходами по индексу

**Режим immediate:**

- Когда `IMM=1`: поле C содержит константу индекса (знаковое расширение -128..+127)
- Когда `IMM=0`: индекс берётся из `reg[C]`

## Система контроля целостности

### CRC32-хеширование состояния

VM32 использует **CRC32 (IEEE 802.3)** для проверки детерминизма выполнения:

```c
uint32_t calculate_registers_hash(void) {
    return vm_config.hash_algo == HASH_CRC32 
        ? crc32(reg, sizeof(reg))
        : fnv1a_hash(reg, sizeof(reg));
}
```

**Логика проверки:**

1. **Начало цикла N**: вычисляется `hash_start[N]`
2. **Конец цикла N**: вычисляется `hash_end[N]`
3. **Проверка**: `hash_end[N-1] == hash_start[N]`?
    - ✅ **OK** — состояние стабильно между циклами
    - ❌ **HASH MISMATCH** — обнаружено недетерминированное изменение

**Применение**: Обнаружение race conditions, недетерминированных операций, сбоев памяти.

## Работа с памятью

### Организация памяти

```
┌────────────────────────────────────────┐ 0x00000000
│  Свободная область (12 КБ)             │
├────────────────────────────────────────┤ 0x00003000 ← PC_START
│  Код программы (инструкции)            │
│  ↓ растёт вниз                         │
├────────────────────────────────────────┤
│  Данные, строки, стек                  │
│  (динамическое размещение)             │
├────────────────────────────────────────┤
│  ...                                   │
└────────────────────────────────────────┘ 0x04000000 (64 МиБ)
```

### API доступа к памяти

```c
// Побайтовый доступ
uint8_t  mr8(uint32_t addr);
void     mw8(uint32_t addr, uint8_t val);

// 32-битные слова (Little-Endian)
uint32_t mr32(uint32_t addr);
void     mw32(uint32_t addr, uint32_t val);
```

### Безопасность памяти

Все строковые операции включают **автоматическую проверку границ**:

```c
size_t safe_strlen_at(uint32_t addr);        // Ограниченный strlen
void safe_memmove(uint32_t dest, uint32_t src, size_t n);
```

## Ограничения и масштабирование

### Текущие ограничения

- **68 опкодов** используются (расширяемо до 127)
- **256 регистров** на инстанс
- **16 экземпляров** каждого типа таймера/счётчика/детектора/защёлки
- **64 МиБ памяти** на инстанс (фиксировано)
- **Не потокобезопасно внутри инстанса** (требуется внешняя синхронизация при параллельном доступе к одному VM)
- **Потокобезопасно между инстансами** (разные VM изолированы)

### Защиты

- Максимум 100 000 инструкций за цикл (защита от зависаний)
- Автоматическая остановка при выходе PC за границы памяти
- Валидация опкодов при выполнении
- Проверка границ массивов для строковых операций
- CRC32-контроль целостности состояния (опционально)

### Масштабирование

**Вертикальное** (один VM):
- До 64 МиБ данных
- До 256 регистров
- Любое количество таймеров (используя ID rotation)

**Горизонтальное** (множественные VM):
- Неограниченное количество независимых инстансов
- Параллельное выполнение (с OpenMP/pthreads)
- Изоляция памяти и состояния

## API управления VM

### Создание и настройка

```c
// Создание VM с настройками по умолчанию
vm_state_t *vm = vm_create();
if (!vm) {
    fprintf(stderr, "Ошибка создания VM\n");
    return -1;
}

// Инициализация
if (vm_init_defaults(vm) != 0) {
    vm_destroy(vm);
    return -1;
}

// Настройка конфигурации
vm->config.cycle_time_ms = 50;         // Цикл 50 мс (20 Гц)
vm->config.enable_hash_check = true;   // Контроль целостности
vm->config.hash_algo = HASH_CRC32;     // CRC32
vm->config.enable_cycle_check = true;  // Предупреждения о перерасходе
```

### Загрузка и выполнение
```c
// Загрузка программ
const char *programs[] = {
    "main.bin",
    "library.bin"
};

if (load_programs(vm, programs, 2) != 0) {
    fprintf(stderr, "Ошибка загрузки программ\n");
    vm_destroy(vm);
    return -1;
}

// Выполнение
int result = run_program(vm);

// Очистка
vm_destroy(vm);
```

### Сброс состояния (без пересоздания)
```c
// Очистка регистров и памяти без освобождения
vm_reset(vm);

// Повторная загрузка другой программы
const char *new_prog[] = {"other.bin"};
load_programs(vm, new_prog, 1);
run_program(vm);
```

### Множественные VM (параллельное выполнение)
```c
// Создание двух независимых VM
vm_state_t *vm1 = vm_create();
vm_state_t *vm2 = vm_create();

vm_init_defaults(vm1);
vm_init_defaults(vm2);

// Разные конфигурации
vm1->config.cycle_time_ms = 100;  // Медленная
vm2->config.cycle_time_ms = 10;   // Быстрая

// Загрузка разных программ
const char *prog1[] = {"slow_task.bin"};
const char *prog2[] = {"fast_task.bin"};

load_programs(vm1, prog1, 1);
load_programs(vm2, prog2, 1);

// Параллельное выполнение (требуется внешняя синхронизация)
#pragma omp parallel sections
{
    #pragma omp section
    { run_program(vm1); }
    
    #pragma omp section
    { run_program(vm2); }
}

vm_destroy(vm1);
vm_destroy(vm2);
```

```c
void op_my_instruction(uint32_t i) {

}
```

**3. Регистрация в `vm32.c`:**

```c
op_ex_f op_ex[OPCODE_COUNT] = {
    /* ... */

    /* ... */
};
```
