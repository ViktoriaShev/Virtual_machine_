
## Введение

VM32 представляет собой специализированную виртуальную машину, разработанную для выполнения программ промышленных программируемых логических контроллеров (ПЛК). Архитектура VM32 обеспечивает поддержку стандартов IEC 61131-3, и предоставляет полный набор функциональных блоков для автоматизации промышленных процессов.

## Архитектура виртуальной машины

### Общие характеристики

VM32 является 32-битной виртуальной машиной с байтовой адресацией памяти. Основные параметры:

- **Разрядность данных**: 32 бита
- **Адресация памяти**: побайтовая (каждый адрес указывает на один байт)
- **Объем памяти**: 64 МБ (67 108 864 байта)
- **Количество регистров**: 256 регистров общего назначения (32-битных)
- **Формат инструкций**: фиксированный, 32 бита
- **Порядок байтов**: Little-Endian

### Организация памяти

Память VM32 представляет собой линейное байтовое адресное пространство размером 64 МиБ. Память используется для:

- **Кода программы**: начиная с адреса 0x3000 (PC_START)
- **Данных**: произвольные области памяти для хранения переменных
- **Строк**: нультерминированные байтовые последовательности
- **Стека**: область для сохранения контекста вызовов

#### Модель доступа к памяти

Виртуальная машина предоставляет функции для безопасного доступа к памяти:

```c
uint8_t  mr8(uint32_t addr)           // чтение байта
void     mw8(uint32_t addr, uint8_t v) // запись байта
uint32_t mr32(uint32_t addr)          // чтение 32-бит слова (LE)
void     mw32(uint32_t addr, uint32_t v) // запись 32-бит слова (LE)
```

При чтении 32-битного слова байты интерпретируются в порядке Little-Endian:

- Младший байт по адресу `addr`
- Старший байт по адресу `addr + 3`

### Регистровый файл

VM32 содержит 256 регистров общего назначения (R0–R255), каждый размером 32 бита. Регистры используются для:

- Хранения промежуточных результатов вычислений
- Передачи параметров между инструкциями
- Хранения адресов данных в памяти
- Управления потоком выполнения

**Специальный регистр RPC (Register Program Counter)**:

- По умолчанию используется регистр R0 (определяется макросом `RPC`)
- Хранит текущий адрес выполняемой инструкции (в байтах)
- Автоматически инкрементируется на 4 после каждой инструкции
- Может быть изменен инструкциями перехода (JMP)

## Формат инструкций

Каждая инструкция VM32 занимает ровно 32 бита и имеет следующую структуру:

```
┌─────────┬─────────┬─────────┬─────────┐
│ Opcode  │    A    │    B    │    C    │
│ 7 бит   │  8 бит  │  8 бит  │  9 бит  │
└─────────┴─────────┴─────────┴─────────┘
  31..25    24..17    16..9     8..0
```

### Поля инструкции

- **Opcode (7 бит)**: код операции (0–127), определяет выполняемое действие
- **A (8 бит)**: индекс регистра назначения (обычно для результата)
- **B (8 бит)**: индекс регистра — первый операнд
- **C (9 бит)**: индекс регистра — второй операнд или непосредственное значение

### Макросы декодирования

```c
OPC(i)  // извлекает код операции (биты 31..25)
RA(i)   // извлекает индекс регистра A (биты 24..17)
RB(i)   // извлекает индекс регистра B (биты 16..9)
RC(i)   // извлекает индекс регистра C (биты 8..0)
```

### Вспомогательные функции доступа к операндам

```c
A(i)        // возвращает индекс регистра A
Bv(i)       // возвращает ЗНАЧЕНИЕ регистра B: reg[RB(i)]
Cv(i)       // возвращает ЗНАЧЕНИЕ регистра C: reg[RC(i)]
SetA_val(i, v) // записывает значение v в регистр A
```

## Система типов данных

VM32 поддерживает типы данных, соответствующие стандарту IEC 61131-3:

### Базовые типы

- **BOOL**: логическое значение (0 = FALSE, ≠0 = TRUE)
- **INT/DINT**: целые числа со знаком (32-битные)
- **UINT/UDINT**: целые числа без знака (32-битные)
- **REAL**: вещественные числа (через приведение к double для вычислений)

### Специализированные типы времени и даты

```c
// Время суток (Time of Day)
typedef struct {
    int32_t hours;    // 0..23
    int32_t minutes;  // 0..59
    int32_t seconds;  // 0..59
} TOD_t;

// Дата (Date)
typedef struct {
    int32_t year;     // полный год (например, 2025)
    int32_t month;    // 1..12
    int32_t day;      // 1..31
} DATE_t;

// Дата и время (DateTime)
typedef struct {
    DATE_t date;
    TOD_t  time;
} DT_t;
```

### Строковые данные

Строки хранятся в памяти как нультерминированные последовательности байтов (C-style strings). Максимальная длина строки ограничена доступной памятью.

## Набор инструкций

VM32 предоставляет 128 опкодов, сгруппированных по функциональному назначению:

### 1. Арифметические операции

Стандартные арифметические операции над 32-битными целыми числами:

|Опкод|Мнемоника|Описание|Операция|
|---|---|---|---|
|0|ADD|Сложение|A ← B + C|
|1|SUB|Вычитание|A ← B - C|
|2|MUL|Умножение|A ← B × C|
|3|DIV|Деление|A ← B ÷ C (целочисленное)|
|4|MOD|Остаток от деления|A ← B mod C|
|5|EXPT|Возведение в степень|A ← B^C|

**Примечания**:

- При делении на ноль результат равен 0
- Операция MOD при делителе 0 возвращает 0

### 2. Математические функции

Трансцендентные и специальные функции (операнд B преобразуется в double для вычисления, результат приводится к uint32_t):

|Опкод|Мнемоника|Описание|Операция|
|---|---|---|---|
|6|ABS|Абсолютное значение|A ← \|B\||
|7|SQRT|Квадратный корень|A ← √B|
|8|LN|Натуральный логарифм|A ← ln(B)|
|9|LOG|Десятичный логарифм|A ← log₁₀(B)|
|10|EXP|Экспонента|A ← e^B|
|11|SIN|Синус|A ← sin(B)|
|12|COS|Косинус|A ← cos(B)|
|13|TAN|Тангенс|A ← tan(B)|
|14|ASIN|Арксинус|A ← arcsin(B)|
|15|ACOS|Арккосинус|A ← arccos(B)|
|16|ATAN|Арктангенс|A ← arctan(B)|

### 3. Логические операции

Побитовые логические операции:

|Опкод|Мнемоника|Описание|Операция|
|---|---|---|---|
|17|AND|Побитовое И|A ← B & C|
|18|OR|Побитовое ИЛИ|A ← B \| C|
|19|XOR|Исключающее ИЛИ|A ← B ⊕ C|
|20|NOT|Побитовое НЕ|A ← ~B|

### 4. Операции сравнения

Все операции сравнения записывают в регистр A результат:

- 1 (TRUE) если условие истинно
- 0 (FALSE) если условие ложно

|Опкод|Мнемоника|Описание|Условие|
|---|---|---|---|
|21|EQ|Равно|B = C|
|22|NE|Не равно|B ≠ C|
|23|GT|Больше|B > C|
|24|GE|Больше или равно|B ≥ C|
|25|LT|Меньше|B < C|
|26|LE|Меньше или равно|B ≤ C|

### 5. Операции с датой и временем

VM32 предоставляет полноценную поддержку работы с датой и временем согласно IEC 61131-3:

|Опкод|Мнемоника|Описание|Результат|
|---|---|---|---|
|27|TIME|Текущее время|Секунды с начала дня|
|28|DATE|Текущая дата|YYYYMMDD (целое число)|
|29|TOD|Время суток|HHMMSS (целое число)|
|30|DT|Дата-время|Упакованное значение|
|31|ADD_TIME|Сложение времен|A ← B + C|
|32|SUB_TIME|Вычитание времен|A ← B - C|

**Извлечение компонентов даты/времени**:

|Опкод|Мнемоника|Описание|
|---|---|---|
|33|YEAR|Текущий год|
|34|MONTH|Текущий месяц (1–12)|
|35|DAY|Текущий день (1–31)|
|36|HOUR|Текущий час (0–23)|
|37|MINUTE|Текущая минута (0–59)|
|38|SECOND|Текущая секунда (0–59)|

**Примечание**: Для получения текущего системного времени используется POSIX-функция `clock_gettime(CLOCK_MONOTONIC)`.

### 6. Строковые операции

VM32 поддерживает богатый набор операций для работы со строками. Все строки хранятся как нультерминированные последовательности байтов в памяти VM.

|Опкод|Мнемоника|Описание|Параметры|
|---|---|---|---|
|39|LEN|Длина строки|A ← длина строки по адресу B|
|40|CONCAT|Конкатенация|Добавить строку C к строке B|
|41|LEFT|Левые символы|Оставить первые C символов строки B|
|42|RIGHT|Правые символы|Оставить последние C символов строки B|
|43|MID|Подстрока|Начать строку с позиции C|
|44|INSERT|Вставка|Вставить строку B в позицию C строки A|
|45|DELETE|Удаление|Удалить C символов с позиции B в строке A|
|46|REPLACE|Замена|Заменить фрагмент строки A на строку B в позиции C|

**Особенности реализации**:

- Все операции выполняются in-place (изменяют исходную строку)
- Автоматическая проверка границ памяти
- Корректная обработка перекрывающихся областей памяти
- Гарантированное завершение строк нуль-терминатором

### 7. Функциональные блоки: таймеры

VM32 поддерживает три типа таймеров согласно IEC 61131-3, каждый с 16 экземплярами (индексы 0–15):

#### TON (Timer On-Delay) — Таймер задержки включения

```c
typedef struct {
    bool enabled;           // флаг активности таймера
    bool input;             // текущее состояние входа
    bool output;            // выходной сигнал
    struct timespec start_time; // момент старта отсчета
    uint32_t preset_ms;     // уставка времени (миллисекунды)
} TON_Timer;
```

**Опкод**: 47 (TON)

**Логика работы**:

1. При переходе входа из 0→1 запоминается момент времени
2. Пока вход активен, отсчитывается время
3. Когда elapsed_time ≥ preset_ms, выход устанавливается в 1
4. При переходе входа в 0, выход немедленно сбрасывается в 0

**Применение**: Задержка включения оборудования, фильтрация кратковременных импульсов

#### TOF (Timer Off-Delay) — Таймер задержки выключения

```c
typedef struct {
    bool enabled;
    bool input;
    bool output;
    struct timespec start_time;
    uint32_t preset_ms;
} TOF_Timer;
```

**Опкод**: 48 (TOF)

**Логика работы**:

1. Пока вход активен (1), выход также активен (1)
2. При переходе входа из 1→0 запоминается момент времени
3. Выход остается активным в течение времени preset_ms
4. Когда elapsed_time ≥ preset_ms, выход сбрасывается в 0

**Применение**: Обеспечение работы оборудования после снятия управляющего сигнала

#### TP (Timer Pulse) — Генератор импульса

```c
typedef struct {
    bool enabled;
    bool input;
    bool output;
    bool pulse_generated;    // флаг завершения импульса
    struct timespec start_time;
    uint32_t preset_ms;
} TP_Timer;
```

**Опкод**: 49 (TP)

**Логика работы**:

1. При переходе входа из 0→1 генерируется импульс
2. Выход устанавливается в 1 на время preset_ms
3. По истечении времени выход сбрасывается в 0
4. Повторные переходы входа игнорируются до завершения импульса

**Применение**: Формирование импульсов фиксированной длительности

#### Использование таймеров в инструкциях

```
Формат инструкции:
  reg[RA] = ID таймера (0..15)
  reg[RB] = состояние входа (0 или 1)
  
После выполнения:
  reg[RA] = состояние выхода таймера (0 или 1)
```

**Пример**: Активация таймера TON с ID=3, вход из регистра R10, результат в R5:

```
TON R5, R10, R3  (где R3 содержит значение 3)
```

### 8. Функциональные блоки: счётчики

VM32 предоставляет три типа счётчиков с 16 экземплярами каждого типа:

```c
typedef struct {
    uint32_t value;    // текущее значение счётчика
    uint32_t preset;   // пороговое значение
} CT_Counter;
```

#### CTU (Counter Up) — Счётчик вверх

**Опкод**: 50 (CTU)

**Логика работы**:

- При переходе входа CU из 0→1 значение счётчика увеличивается на 1
- Без автоматического сброса (требуется явное обнуление)

#### CTD (Counter Down) — Счётчик вниз

**Опкод**: 51 (CTD)

**Логика работы**:

- При переходе входа CD из 0→1 значение счётчика уменьшается на 1
- Останавливается на 0 (не уходит в отрицательные значения)

#### CTUD (Counter Up-Down) — Двунаправленный счётчик

**Опкод**: 52 (CTUD)

**Логика работы**:

- Имеет два входа: CU (count up) и CD (count down)
- При фронте на CU — увеличение
- При фронте на CD — уменьшение
- Результат: разность между счётчиками вверх и вниз

**Формат использования**:

```
reg[RA] = ID счётчика (0..15)
reg[RB] = состояние входа CU (для CTU/CTUD) или CD (для CTD)
reg[RC] = состояние входа CD (только для CTUD)

После выполнения:
reg[RA] = текущее значение счётчика
```

### 9. Операции выбора и ограничения

#### LIMIT — Ограничение значения

**Опкод**: 53 (LIMIT)

**Операция**: `A ← clamp(A, B, C)` где B — минимум, C — максимум

**Применение**: Обеспечение нахождения значения в заданных пределах

#### SEL — Выбор одного из двух значений

**Опкод**: 54 (SEL)

**Операция**:

```
if (B != 0)
    A ← mem[C]      // первое значение
else
    A ← mem[C+4]    // второе значение
```

**Применение**: Условный выбор между двумя источниками данных

#### MUX — Мультиплексор

**Опкод**: 55 (MUX)

**Операция**: `A ← mem[B + C*4]`

**Применение**: Выбор одного значения из массива по индексу

### 10. Инструкции управления потоком

#### JMP — Безусловный переход

**Опкод**: 56 (JMP)

**Операция**: `PC ← B_val` (переход по адресу, указанному в B)

#### JMP_IF — Условный переход (если истина)

**Опкод**: 57 (JMP_IF)

**Операция**:

```
if (C_val != 0)
    PC ← B_val
```

#### JMP_IF_NOT — Условный переход (если ложь)

**Опкод**: 58 (JMP_IF_NOT)

**Операция**:

```
if (C_val == 0)
    PC ← B_val
```

**Примечание**: Адреса переходов указываются в байтах. Инструкции выравнены по 4 байта, поэтому адреса должны быть кратны 4.

## Цикл выполнения программы

Основной цикл VM32 (функция `run_program()`) выполняет следующие шаги:

```
1. Инициализация: PC ← PC_START (0x3000)

2. Основной цикл:
   a. Проверка границ: если PC выходит за пределы памяти — останов
   b. Чтение инструкции: instr ← mem[PC] (32 бита)
   c. Декодирование опкода: opcode ← OPC(instr)
   d. Сохранение текущего PC: old_pc ← PC
   e. Выполнение: op_ex[opcode](instr)
   f. Автоинкремент PC (если не было явного перехода):
      if (PC == old_pc) PC ← PC + 4
   g. Проверка флага running
   
3. Завершение при остановке или ошибке
```

### Обработка ошибок

VM32 останавливается в следующих случаях:

- PC выходит за пределы памяти
- Встречен неизвестный опкод
- Флаг `running` установлен в false

## Особенности реализации

### Потокобезопасность

Текущая реализация VM32 **не является потокобезопасной**. Для использования в многопоточной среде требуется:

- Внешняя синхронизация доступа к глобальным структурам
- Отдельные экземпляры таймеров и счётчиков для каждого потока

### Работа с временем

VM32 использует `clock_gettime(CLOCK_MONOTONIC)` для работы таймеров, что обеспечивает:

- Независимость от изменений системного времени
- Разрешение до наносекунд (на поддерживаемых системах)
- Устойчивость к переводам часов

### Безопасность памяти

Все операции с памятью включают проверки границ:

- `safe_mem_remaining(addr)` — вычисляет доступное пространство
- `safe_strlen_at(addr)` — безопасное определение длины строки
- `safe_memcpy_from_to()` — копирование с проверкой границ
- `safe_memmove()` — перемещение с проверкой перекрытий

### Оптимизация производительности

Для достижения максимальной производительности:

- Инструкции декодируются с использованием битовых операций
- Таблица функций-обработчиков (`op_ex[]`) обеспечивает прямой вызов
- Минимальные накладные расходы на проверки в критических циклах

## Загрузка и выполнение программ

### Формат программных файлов

Программы для VM32 представляют собой бинарные файлы, содержащие последовательность 32-битных инструкций. Файл загружается в память начиная с адреса PC_START (0x3000).

### Загрузка программы

```c
void load_program(const char *filename);
```

Функция загружает бинарный файл в память VM начиная с адреса 0x3000.

### Запуск виртуальной машины

```bash
./vm32 program.bin
```

Где `program.bin` — скомпилированная программа для VM32.


## Расширение функциональности

Для добавления новых инструкций необходимо:

1. Определить прототип функции в `vm32.h`:

```c
void op_my_instruction(uint32_t i);
```

2. Реализовать функцию в `funcs.c`:

```c
void op_my_instruction(uint32_t i) {
    // реализация операции
    SetA_val(i, result);
}
```

3. Добавить указатель на функцию в массив `op_ex[]` в `vm32.c`
    
4. Обновить `OPCODE_COUNT` при необходимости
