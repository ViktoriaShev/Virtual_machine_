

# 1) Формат и диапазоны

Инструкция 32-битная, поля (слева направо):

```
[ opcode: 7 бит | A: 8 бит | B: 8 бит | C: 9 бит ]
```

Диапазоны (в десятичном виде):

- opcode: 0 .. 127 (7 бит)
    
- A: 0 .. 255 (8 бит)
    
- B: 0 .. 255 (8 бит)
    
- C: 0 .. 511 (9 бит)
    

Формула сборки (то, что ты и привёл):

```
word = (opcode << 25) | (A << 17) | (B << 9) | C
```

Сдвиг на `n` бит эквивалентен умножению на `2^n`.

# 2) Почему смещения такие

Всего 32 бита:

- opcode занимает старшие 7 бит: их сдвигаем на 25 (32−7).
    
- поле A идёт после opcode → сдвиг на 17 (25−8).
    
- поле B → сдвиг на 9 (17−8).
    
- поле C остаётся в младших 9 битах → без сдвига.
    

# 3) Шаги ручного вычисления (по цифрам)

Возьмём пример `ADD 2 0 1` (opcode=0, A=2, B=0, C=1).

1. Посчитать каждую часть как целое умножение на степень двойки:
    
    - `opcode << 25` = `0 * 2^25` = `0`
        
    - `A << 17` = `2 * 2^17` = `2 * 131072` = `262144`
        
    - `B << 9` = `0 * 512` = `0`
        
    - `C` = `1`
        
2. Сложить:
    
    ```
    word = 0 + 262144 + 0 + 1 = 262145
    ```
    
3. Представления:
    
    - десятичное: `262145`
        
    - шестнадцатеричное: `0x00040001` (проверь: 262144 = 0x00040000, +1 → 0x00040001)
        
    - бинарное (32 бит): `00000000 00000100 00000000 00000001` → `00000000000001000000000000000001`
        

То же для `HALT` (opcode=59, A=B=C=0):

- `59 << 25 = 59 * 33554432 = 1979711488`
    
- hex: `0x76000000` (как в твоём примере).
    

# 4) Как вручную распарсить (декодировать) слово обратно

Если у тебя `word` (32-бит целое), извлекаешь поля масками и сдвигами:

```
opcode = (word >> 25) & 0x7F      # 0x7F = 0b1111111
A      = (word >> 17) & 0xFF      # 0xFF = 0b11111111
B      = (word >> 9)  & 0xFF
C      = word & 0x1FF             # 0x1FF = 0b1_1111_1111 (9 бит)
```

Проверка: `disassemble(0x00040001)` вернёт `(0,2,0,1)`; `disassemble(0x76000000)` вернёт `(59,0,0,0)`.

# 5) Полезные маски и значения (шестнадцатерично / двоично)

- mask opcode (7 бит): `0x7F`
    
- mask A/B (8 бит): `0xFF`
    
- mask C (9 бит): `0x1FF`
    

Сдвиги:

- opcode: >>25 / <<25
    
- A: >>17 / <<17
    
- B: >>9 / <<9
    
- C: no shift
    

# 6) Частые ошибки и на что смотреть

- **Выход за диапазон.** Всегда проверяй, что поля не превышают свои лимиты (напр., C ≤ 511). Иначе в результате будут «забиты» соседние биты.
    
- **Знак.** Все поля — беззнаковые. Никогда не интерпретируй их как signed при сборке.
    
- **Порядок байтов (endianness).** Формула даёт 32-битное слово; при записи в память/файл следи за порядком байтов, который использует твоя VM (big/little endian).
    
- **Визуальное форматирование.** При отладке удобно смотреть hex 8 символов и 32-битный bin рядом.
    

# 7) Примеры (важные контрольные точки)

- Минимальные значения: `(0,0,0,0)` → `0x00000000`.
    
- Пример из твоего лога: `(0,2,0,1)` → `0x00040001`.
    
- HALT: `(59,0,0,0)` → `0x76000000`.
    
- Максимальные поля: `(127,255,255,511)` → `0xFFFFFFFF` (всю 32-битную маску).
    

# 8) Быстрый Python-шаблон (копировать — вставить)

```python
def assemble(opcode, A, B, C):
    if not (0 <= opcode <= 0x7F): raise ValueError("opcode out of range")
    if not (0 <= A <= 0xFF): raise ValueError("A out of range")
    if not (0 <= B <= 0xFF): raise ValueError("B out of range")
    if not (0 <= C <= 0x1FF): raise ValueError("C out of range")
    return (opcode << 25) | (A << 17) | (B << 9) | C

def disassemble(word):
    opcode = (word >> 25) & 0x7F
    A = (word >> 17) & 0xFF
    B = (word >> 9) & 0xFF
    C = word & 0x1FF
    return opcode, A, B, C
```

# 9) Как быстро вручную переводить в hex (полезный трюк)

- Считай каждую часть отдельно и переводи в hex:
    
    - `A << 17` = `A * 0x20000` (потому что `2^17 = 0x20000`).
        
    - `B << 9` = `B * 0x200` (потому что `2^9 = 0x200`).
        
    - `opcode << 25` = `opcode * 0x2000000` (`2^25 = 0x2000000`).
        
- Затем складывай hex-части — удобно сверять с калькулятором/скриптом.
    

# Итог

- Сборка = сдвиги + побитовое OR (или сложение эквивалентно).
    
- Декод = сдвиг вправо + маска для нужной ширины.
    
- Всегда проверяй диапазоны полей и учти порядок байтов при записи.
