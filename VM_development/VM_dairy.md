### Implementing the VM[Permalink](https://www.andreinc.net/2021/12/01/writing-a-simple-vm-in-less-than-125-lines-of-c#implementing-the-vm "Permalink")

Our VM functions like this:

- We load the program into the main memory;
- In the `RPC` register, we keep the current instruction that we need to execute;
- We obtain the _Operation Code_ (first 4 bits) from the instruction and based on that, we _decode_ the rest of the parameters.;
- We execute the method associated with the given instruction;
- We increment `RPC` and we continue with the next instruction;

### 🔷 **Твоя цель (переформулирую для чёткости)**

✅ Написать **транслятор из языка ST (Structured Text, например, IEC 61131-3)** в **ассемблер** (под конкретный контроллер).

✅ Создать **виртуальную машину (ВМ)**, которая:

- Исполняет этот ассемблер (байткод или псевдоассемблер).
    
- Работает **как дискретный автомат** (т.е. с конечными состояниями, переходами, переменными состояний).
    

✅ Работает **на самом контроллере** (embedded execution), а не только как PC-симулятор.

---

### 🔷 **Ключевые аспекты задачи**

#### 1. **Зачем тебе ВМ?**

ВМ в данном случае выполняет роль **интерпретатора байткода**, а именно:

- Обеспечивает переносимость ST-кода без перекомпиляции под каждый CPU.
    
- Позволяет реализовать функции ST (циклы, IF, арифметику) на простом контроллере без полноценного компилятора ST под него.
    
- Даёт возможность реализовать дискретный автомат на базе байткода (каждая инструкция – переход состояния).
    

---

#### 2. **Что такое “транслятор ST → ассемблер” в твоей задаче?**

Ты хочешь **трансляцию не в реальный CPU-ассемблер**, а:

✅ Либо в **байткод твоей ВМ** (псевдо-ассемблер), который будет выполняться интерпретатором на контроллере.

✅ Либо в **реальный машинный код**, если ты пишешь полноценный компилятор ST под ISA контроллера (сложнее, требует генерации бинарей под архитектуру).

---

#### 3. **Дискретный автомат и ВМ**

Если ВМ реализована как **дискретный автомат**, это значит:

- Каждая инструкция ВМ соответствует **переходу** или **состоянию автомата**.
    
- Основная петля (main loop) – это цикл автомата, который проверяет входы, изменяет состояния, исполняет действия (outputs), меняет регистры/память.
    

---

### 🔷 **Практическая реализация (общая архитектура)**

#### **[Step 1] Дизайн байткода / ассемблера для ВМ**

1. Определяешь **набор инструкций (ISA)**, например:
    

|OPCODE|Описание|Операнды|
|---|---|---|
|MOV|копирование|dst, src|
|ADD|сложение|dst, src1, src2|
|CMP|сравнение|src1, src2|
|JMP|безусловный переход|address|
|JZ|переход, если 0|address|
|OUT|вывести в output pin|pin, value|
|IN|считать input|dst, pin|

Это минимальная база.

---

#### **[Step 2] Транслятор ST → байткод**

✅ Парсишь ST-код  
✅ Генерируешь последовательность инструкций твоей ВМ

Например:

```st
IF x > 0 THEN
    y := y + 1;
END_IF;
```

Трансляция:

```
CMP x, 0
JLE skip_inc
ADD y, y, 1
skip_inc:
```

---

#### **[Step 3] Реализация виртуальной машины на контроллере**

✅ Основной loop: fetch → decode → execute

```c
while (1) {
    opcode = fetch();
    switch(opcode) {
        case MOV: ...
        case ADD: ...
        case JMP: ...
    }
}
```

✅ ВМ работает **как дискретный автомат**, где:

- Каждое состояние – текущая инструкция
    
- Переход – выполнение инструкции и переход к следующей
    

---

#### **[Step 4] Оптимизации под контроллер**

- Прерывания и таймеры для циклов опроса входов.
    
- Управление энергопотреблением (sleep, wakeup).
    
- Возможность прошивки байткода во Flash и выполнения из неё.
    

---

### 🔷 **Почему это полезно в промышленности?**

✅ **Переносимость** ST-кода на разные микроконтроллеры без перекомпиляции.

✅ **Мини-интерпретатор** как ядро soft-PLC на слабом CPU.

✅ **Дискретная логика как FSM** (finite state machine) легко реализуется на ВМ, при этом поддерживается высокоуровневое описание в ST.
