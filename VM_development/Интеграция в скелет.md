## Модель исполнения

```
┌────────────┐
│ Scheduler  │
│ (system)   │
└─────┬──────┘
      │ tick()
┌─────▼──────┐
│VM32Component│
│(IComponent)│
└─────┬──────┘
      │ executeCycle()
┌─────▼──────┐
│ VM32Engine │
│(C++ adapter) │
└─────┬──────┘
      │
┌─────▼──────┐
│ VM32 C core│
│  (VM)      │
└────────────┘

```

# Краткая идея

1. Вынести `main` / вечный цикл из `vm32.c` и предоставить C API: `vm32_init`, `vm32_load_programs`, `vm32_execute_cycle`, `vm32_shutdown`, `vm32_request_stop`. +
    
2. Сделать тонкий C++ адаптер `VM32Engine` (в `iec/runtime/`) который вызывает эти C-функции. +
    
3. Сделать `VM32Component` как `IComponent` (и/или `ITickable`) — в `start()` зарегистрировать себя в TaskManager/Scheduler (или просто зарегистрировать как tickable) и в `tick()` вызывать `engine.executeCycle()`. +
    
4. Подключить старые C-файлы в CMake как статическую библиотеку и линковать её в компонент.
    
5. Постепенно заменить printf/log_file на System logger (опционально — можно отложить).+
