# Ключевая мысль (самое важное)

> **VM32 не должна “исполнять файлы”.  
> Она должна исполнять _загруженные программы_ (modules),  
> а загрузка — это отдельный слой.**

То есть:

- VM **живет постоянно**, крутит циклы
    
- бинарники **подгружаются / обновляются асинхронно**
    
- VM в каждом цикле выполняет **активный набор модулей**
    

Это прямо **классическая PLC-модель** (scan cycle).

## Вариант C — «Менеджер модулей + папка»

**Рекомендую именно его**

Архитектура:

`/programs/  ├── main.bin  ├── io.bin  ├── control.bin  └── vision.bin`

VM:

- на старте: загружает всё из папки
    
- дальше:
    
    - либо по таймеру
        
    - либо по сигналу
        
    - либо по команде  
        проверяет изменения и **перезагружает модуль**
        

💡 Это промышленный, правильный вариант.
