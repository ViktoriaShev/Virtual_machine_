# IEC Diagnostics — Architecture Skeleton

## 1. Назначение документа

Данный документ описывает архитектурный каркас подсистемы диагностики
и runtime-состояния IEC в проекте **system** на этапе ШАГА 14.

Документ фиксирует:
- модель runtime-состояния
- точки диагностики
- границы ответственности подсистемы

Реальная обработка ошибок и логирование не рассматриваются.

---

## 2. Общая концепция диагностики IEC

Подсистема диагностики IEC предназначена для:
- отражения текущего состояния исполнения
- фиксации ошибок выполнения
- подготовки к трассировке и отладке

Диагностика:
- не управляет исполнением
- не влияет на Scheduler
- является пассивным наблюдателем

---

## 3. IecRuntimeState

`IecRuntimeState` представляет минимальное состояние выполнения IEC Program.

Текущие статусы:
- `Idle` — Program не выполняется
- `Running` — выполняется цикл
- `Error` — зафиксирована ошибка

Назначение:
- единая точка хранения состояния
- простой и расширяемый интерфейс

---

## 4. IecDiagnostics

`IecDiagnostics` агрегирует runtime-состояние и события выполнения.

Функции:
- фиксация начала цикла
- фиксация окончания цикла
- переход в состояние ошибки

На текущем этапе:
- не хранит сообщений
- не содержит кодов ошибок
- не интегрирован с логированием

---

## 5. Связь с Execution Context

`IecExecutionContext`:
- использует `IecDiagnostics`
- уведомляет о начале и конце цикла

Таким образом:
- диагностика отделена от execution engine
- context выступает точкой интеграции

---

## 6. Место в модели исполнения

Упрощённая схема:

```
Scheduler
  -> Task
      -> IEC Program
          -> Execution Engine
              -> Execution Context
                  -> Diagnostics
```

Диагностика:
- не знает о Scheduler
- не знает о Task
- работает только в контексте Program

---

## 7. Детерминизм

Подсистема диагностики проектируется с учётом:
- отсутствия побочных эффектов
- минимального влияния на исполнение
- предсказуемости состояния

Все изменения состояния выполняются:
- в строго определённых точках
- синхронно с tick-loop

---

## 8. Ограничения текущего этапа

На текущем этапе отсутствуют:
- коды ошибок
- сообщения диагностики
- уровни severity
- интеграция с логгером
- remote diagnostics

Все ограничения являются **осознанными**.
