# Lifecycle / Startup Orchestration — Architecture Skeleton

## 1. Назначение документа

Данный документ описывает архитектурный каркас управления жизненным циклом
в проекте **system** на этапе ШАГА 19.

Документ фиксирует:
- фазы жизненного цикла системы
- порядок инициализации и остановки
- центральную точку управления жизненным циклом

Реальные state machine и обработка ошибок не рассматриваются.

---

## 2. Общая концепция Lifecycle

Lifecycle Layer предназначен для:
- формализации этапов работы системы
- упорядочивания запуска и остановки
- отделения orchestration от бизнес-логики

Lifecycle:
- не выполняет работу системы
- не содержит IEC-логики
- управляет порядком вызовов

---

## 3. LifecyclePhase

`LifecyclePhase` — перечисление фаз жизненного цикла.

Фазы:
- `Created` — система создана
- `Initialized` — выполнена инициализация
- `Started` — компоненты запущены
- `Running` — выполняются tick-циклы
- `Stopped` — система остановлена
- `Shutdown` — завершение работы

Фазы задают **глобальное состояние системы**.

---

## 4. LifecycleController

`LifecycleController` — центральный контроллер жизненного цикла.

Ответственность:
- хранение текущей фазы
- перевод системы между фазами
- единая точка orchestration

LifecycleController:
- не знает о компонентах напрямую
- не управляет ресурсами
- используется верхним уровнем (main)

---

## 5. Связь с ComponentManager

ComponentManager:
- отвечает за init/start/stop компонентов

LifecycleController:
- определяет *когда* эти вызовы происходят
- задаёт порядок фаз

Таким образом:
- orchestration и execution разделены

---

## 6. Место в архитектуре

Упрощённая схема:

```
main()
  -> LifecycleController
      -> ComponentManager
          -> System Layer
          -> IEC Runtime
```

LifecycleController:
- управляет последовательностью
- не вмешивается в детали

---

## 7. Детерминизм

Lifecycle проектируется с учётом:
- фиксированного порядка фаз
- отсутствия скрытых переходов
- явных точек старта и остановки

Каждая фаза:
- достигается явно
- не пропускается неявно

---

## 8. Ограничения текущего этапа

На текущем этапе отсутствуют:
- state machine
- проверки допустимости переходов
- rollback при ошибках
- асинхронные переходы

Все ограничения являются **осознанными**.
