# Fieldbus / Communication Layer — Architecture Skeleton

## 1. Назначение документа

Данный документ описывает архитектурный каркас слоя коммуникаций (Fieldbus)
в проекте **system** на этапе ШАГА 17.

Документ фиксирует:
- роль fieldbus слоя
- основные сущности
- границы ответственности

Реальные протоколы и тайминги не рассматриваются.

---

## 2. Общая концепция Fieldbus Layer

Fieldbus Layer предназначен для:
- абстрагирования коммуникационных протоколов
- отделения устройств от транспорта
- подготовки к промышленным шинам и сетям

Fieldbus Layer:
- не содержит IEC-логики
- не знает о Program или Task
- используется System Layer

---

## 3. Fieldbus

`Fieldbus` представляет собой конкретный транспорт или шину.

Примеры будущих реализаций:
- CAN
- Modbus (RTU / TCP)
- EtherCAT
- TCP / UDP

Fieldbus отвечает за:
- инициализацию транспорта
- управление ресурсами
- завершение работы

---

## 4. FieldbusFrame

`FieldbusFrame` — универсальное представление кадра данных.

Содержит:
- идентификатор
- полезную нагрузку (payload)

Frame:
- не содержит семантики данных
- интерпретируется на уровне выше

---

## 5. FieldbusChannel

`FieldbusChannel` представляет логический канал связи поверх fieldbus.

Назначение:
- отправка кадров
- приём кадров

Channel:
- может представлять device, node или endpoint
- скрывает детали маршрутизации

---

## 6. FieldbusManager

`FieldbusManager` управляет всеми fieldbus экземплярами.

Ответственность:
- владение bus объектами
- инициализация всех bus
- корректное завершение работы

FieldbusManager:
- не знает о протоколах
- не знает о данных IEC
- используется System Layer

---

## 7. NullFieldbus

`NullFieldbus` — заглушка коммуникационного слоя.

Назначение:
- тестирование архитектуры
- placeholder для будущих реализаций
- отсутствие реального обмена

---

## 8. Связь с System Layer

Fieldbus Layer:
- используется System Layer
- предоставляет транспорт для устройств

System Layer:
- реализует конкретные устройства
- использует fieldbus для обмена

IEC Runtime:
- полностью изолирован от fieldbus

---

## 9. Детерминизм и безопасность

Fieldbus Layer может быть:
- асинхронным
- буферизованным
- неблокирующим

Но:
- IEC Runtime взаимодействует только через синхронные точки
- детерминизм tick-loop сохраняется

---

## 10. Ограничения текущего этапа

На текущем этапе отсутствуют:
- реальные протоколы
- тайминги
- обработка ошибок
- конфигурация каналов

Все ограничения являются **осознанными**.
