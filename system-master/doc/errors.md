# Error Handling / Fault Model — Architecture Skeleton

## 1. Назначение документа

Данный документ описывает архитектурный каркас модели ошибок и отказов
в проекте **system** на этапе ШАГА 20.

Документ фиксирует:
- понятия ошибок и отказов
- fault domains
- правила распространения ошибок

Реальная обработка ошибок и восстановление не рассматриваются.

---

## 2. Общая концепция Error Handling

Модель ошибок предназначена для:
- формализации отказов в системе
- предсказуемого поведения при ошибках
- подготовки к диагностике и recovery

Ошибка:
- не обязательно приводит к остановке системы
- должна быть локализуема
- должна быть наблюдаема

---

## 3. Типы ошибок

В системе выделяются следующие категории ошибок:

- **Configuration errors**
  - неверная конфигурация
  - отсутствующие компоненты

- **Runtime errors**
  - ошибки выполнения логики
  - некорректные данные

- **System errors**
  - ошибки устройств
  - ошибки коммуникаций

---

## 4. Fault Domains

Fault Domain — область, в пределах которой ошибка считается локальной.

Примеры fault domains:
- IEC Program
- Task
- Device
- Fieldbus
- System

Ошибка в одном domain:
- не должна автоматически ломать другие domains
- должна быть изолируема архитектурно

---

## 5. Propagation Model

Распространение ошибок подчиняется правилам:

- ошибка поднимается только до границы domain
- пересечение domain требует явного решения
- глобальные ошибки фиксируются централизованно

Propagation:
- не должен быть неявным
- не должен быть неконтролируемым

---

## 6. Связь с Diagnostics

Diagnostics:
- фиксирует факт ошибки
- хранит состояние системы
- не принимает решений о recovery

Error Handling:
- использует diagnostics как источник информации
- не смешивается с логированием

---

## 7. Реакция на ошибки

На текущем этапе допускаются реакции:
- фиксация ошибки
- перевод системы в безопасное состояние
- остановка execution

Автоматическое восстановление:
- **не реализуется**
- закладывается архитектурно

---

## 8. Детерминизм и безопасность

Модель ошибок проектируется с учётом:
- воспроизводимости поведения
- отсутствия скрытых переходов
- явных точек обработки

Ошибки:
- не должны приводить к неопределённому состоянию
- не должны нарушать tick-loop без явного решения

---

## 9. Ограничения текущего этапа

На текущем этапе отсутствуют:
- error codes
- exception hierarchy
- recovery logic
- retry policies

Все ограничения являются **осознанными**.
