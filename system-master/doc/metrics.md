# Monitoring / Metrics — Architecture Skeleton

## 1. Назначение документа

Данный документ описывает архитектурный каркас подсистемы мониторинга
и метрик в проекте **system** на этапе ШАГА 22.

Документ фиксирует:
- назначение метрик
- типы метрик
- связи с logging, diagnostics и lifecycle

Реальная реализация сбора и экспорта метрик не рассматривается.

---

## 2. Общая концепция Monitoring / Metrics

Подсистема Metrics предназначена для:
- количественного наблюдения за системой
- оценки состояния runtime
- поддержки эксплуатации и анализа производительности

Metrics:
- не управляют системой
- не влияют на поведение runtime
- являются пассивными наблюдателями

---

## 3. Типы метрик

Предполагаемые типы метрик:

- **Counters**
  - количество событий
  - ошибки
  - циклы исполнения

- **Gauges**
  - текущее состояние
  - размеры очередей
  - фазы lifecycle

- **Timers**
  - длительность операций
  - execution cycle time

---

## 4. Границы ответственности

Metrics:
- собирают числовые данные
- не принимают решений
- не заменяют logging

Logging:
- фиксирует события
- предоставляет контекст

Diagnostics:
- хранит состояние
- может быть источником метрик

---

## 5. Связь с Lifecycle

Lifecycle предоставляет:
- точки переходов фаз
- источники метрик состояния

Примеры:
- текущая фаза системы
- количество запусков
- время работы

---

## 6. Связь с Execution Engine

Execution Engine может поставлять:
- количество execution cycles
- время выполнения цикла
- количество выражений

Metrics:
- не вмешиваются в порядок выполнения
- не изменяют семантику

---

## 7. Связь с System Layer

System Layer может предоставлять:
- состояние устройств
- состояние fieldbus
- количество ошибок IO

Metrics:
- агрегируют данные
- не управляют устройствами

---

## 8. Детерминизм и безопасность

Сбор метрик:
- не должен блокировать execution
- не должен влиять на тайминги
- должен быть отключаемым

Все операции:
- выполняются в строго определённых точках
- не изменяют состояние runtime

---

## 9. Ограничения текущего этапа

На текущем этапе отсутствуют:
- хранилище метрик
- экспорт (Prometheus, etc.)
- агрегация по времени
- labels / dimensions

Все ограничения являются **осознанными**.
