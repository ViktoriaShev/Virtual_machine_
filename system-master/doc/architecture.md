# Project system — Architecture Overview (v1.1)

## 1. Назначение документа

Данный документ фиксирует текущее архитектурное состояние проекта **system**
на момент завершения ШАГОВ 1–5 разработки.

Документ является **базовой точкой отсчёта**:
- для дальнейшей разработки,
- для code review,
- для онбординга новых разработчиков.

---

## 2. Назначение проекта

**system** — это детерминированный runtime-каркас на C++20 для
промышленных, встроенных и инфраструктурных систем.

Целевые свойства:
- предсказуемое поведение
- управляемый жизненный цикл
- строгая архитектурная дисциплина
- расширяемость без переписывания ядра

Проект не является:
- фреймворком общего назначения
- high-level application framework
- экспериментальной средой

---

## 3. Архитектурные принципы

### 3.1 Component-Oriented Architecture

Все логические сущности системы представлены в виде компонентов с
явным жизненным циклом:

- init()
- start()
- stop()

Компоненты:
- не создают другие компоненты
- не владеют глобальным состоянием
- не используют singleton’ы

---

### 3.2 Inversion of Control

Все зависимости разрешаются через **SystemBus**.

Запрещено:
- прямое создание зависимостей внутри компонентов
- хранение глобальных указателей
- использование статического состояния

---

### 3.3 Determinism First

Архитектура проектируется с прицелом на:
- deterministic execution
- контроль порядка вызовов
- воспроизводимость поведения

Потоки, таймеры и асинхронность будут вводиться **осознанно и ограниченно**.

## 5. Core Interfaces

### 5.1 IComponent

Контракт любого компонента runtime.

Гарантии:
- `init()` — подготовка ресурсов
- `start()` — начало работы
- `stop()` — обязательное освобождение ресурсов

---

### 5.2 ComponentManager

Единая точка управления жизненным циклом.

Гарантии порядка:
- init: прямой
- start: прямой
- stop: обратный

Это критично для корректного shutdown.

---

## 6. SystemBus

SystemBus выполняет роль:
- service locator
- dependency resolver

Характеристики:
- типобезопасный
- синхронный
- без ownership сервисов
- без логики жизненного цикла

SystemBus не:
- управляет потоками
- управляет временем
- реализует события напрямую

---

## 7. Logging Subsystem

### 7.1 System Logging

`ISystemLog` — низкоуровневый интерфейс вывода.

Текущая реализация:
- POSIX stdout/stderr

---

### 7.2 Core Logging

`LoggerComponent`:
- мост между Core и System
- единая точка логирования
- регистрирует `ILogger` в SystemBus

Компонентам запрещено использовать `std::cout`.

---

## 8. Event Subsystem

### 8.1 Event Model

События:
- типизированные
- синхронные
- доставляются в том же потоке

Используются для:
- уведомлений
- loosely-coupled взаимодействия
- реакций на состояние системы

---

### 8.2 Ограничения Event System

На текущем этапе:
- нет очередей
- нет приоритетов
- нет асинхронности

Это сделано осознанно.

---

## 9. Entry Point

`main.cpp` — composition root.

Только здесь допускается:
- создание компонентов
- сборка системы
- wiring зависимостей

---

## 10. Текущее состояние

Реализовано:
- компонентная модель
- lifecycle management
- SystemBus
- logging
- events
- строгая сборка
- документация

Не реализовано:
- scheduler
- tasks
- IEC runtime
- drivers
- communication stack
