# System Layer — Architecture Skeleton

## 1. Назначение документа

Данный документ описывает архитектурный каркас **System Layer**
в проекте **system** на этапе ШАГА 16.

Документ фиксирует:
- роль System Layer
- модель устройств
- границы ответственности между слоями

Реальная работа с оборудованием и коммуникациями не рассматривается.

---

## 2. Общая концепция System Layer

System Layer является нижним слоем runtime и предназначен для:
- интеграции с внешним миром
- управления устройствами
- изоляции IEC Runtime от hardware details

System Layer:
- не содержит IEC-логики
- не знает о Program, Task, Expression
- управляется через компоненты runtime

---

## 3. Device

`Device` — абстракция внешнего устройства.

Назначение:
- представление hardware, симулятора или шины
- единый жизненный цикл
- точка расширения для драйверов

Интерфейс Device включает:
- `init()`
- `shutdown()`
- `name()`

Device:
- не знает о IEC
- не содержит бизнес-логики
- может использовать любые системные ресурсы

---

## 4. DeviceManager

`DeviceManager` управляет всеми устройствами System Layer.

Ответственность:
- владение объектами Device
- инициализация устройств
- корректное завершение работы

DeviceManager:
- не знает о конкретных типах устройств
- не знает о IO Binding
- используется компонентами верхнего уровня

---

## 5. NullDevice

`NullDevice` — заглушка устройства.

Назначение:
- тестирование архитектуры
- placeholder для будущих драйверов
- демонстрация жизненного цикла Device

NullDevice:
- всегда успешно инициализируется
- не выполняет действий
- не взаимодействует с IO

---

## 6. Связь с IO Binding

System Layer и IO Binding:
- концептуально разделены
- соединяются через `IecIoEndpoint`

System Layer:
- реализует конкретные IO endpoints
- поставляет данные во внешний мир

IO Binding:
- использует endpoints
- не знает об устройстве целиком

---

## 7. Границы с IEC Runtime

Чёткие архитектурные границы:

- IEC Runtime **не знает** о Device
- Device **не знает** о IEC
- Связь осуществляется через абстракции

Это обеспечивает:
- переносимость
- тестируемость
- детерминизм IEC Runtime

---

## 8. Детерминизм и безопасность

System Layer может быть:
- асинхронным
- многопоточным
- event-driven

Но:
- IEC Runtime видит только синхронные операции
- все данные подаются через tick-loop

---

## 9. Ограничения текущего этапа

На текущем этапе отсутствуют:
- реальные драйверы
- fieldbus реализации
- error handling устройств
- hot-plug

Все ограничения являются **осознанными**.
