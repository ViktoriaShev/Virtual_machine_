# Scheduler — Architecture and Usage

## 1. Назначение

Scheduler является центральным механизмом детерминированного исполнения логики
в runtime-проекте **system**.

Он вводится на ШАГЕ 6 архитектурного плана и служит фундаментом для:
- Task Manager
- IEC runtime
- циклического PLC-сканирования
- контролируемого исполнения пользовательской логики

---

## 2. Основная идея

Scheduler реализует **детерминированный tick-loop**:

- нет потоков
- нет таймеров ОС
- нет скрытой асинхронности
- все задачи вызываются в строго определённом порядке

Каждый вызов `tick()` соответствует **одному логическому циклу исполнения**.

---

## 3. ITickable

Интерфейс задачи, исполняемой Scheduler’ом.

```cpp
struct ITickable {
    virtual ~ITickable() = default;
    virtual void tick() = 0;
};
```

Требования:
- `tick()` не должен блокироваться
- `tick()` не должен выполнять I/O напрямую
- `tick()` должен быть максимально детерминированным

---

## 4. Scheduler

Класс `Scheduler` отвечает за:
- хранение списка задач
- последовательный вызов `tick()` у каждой задачи

Характеристики:
- задачи добавляются явно
- порядок вызова соответствует порядку регистрации
- Scheduler не владеет задачами

Scheduler **не**:
- управляет временем
- измеряет длительность
- запускает потоки

---

## 5. SchedulerComponent

`SchedulerComponent` — компонент-обёртка над `Scheduler`.

Функции:
- управляется `ComponentManager`
- регистрирует `Scheduler` как сервис в `SystemBus`
- интегрирует Scheduler в архитектуру runtime

Это позволяет:
- получать Scheduler через `SystemBus`
- добавлять задачи из других компонентов
- не нарушать инверсию зависимостей

---

## 6. Жизненный цикл

- `init()`:
  - регистрация Scheduler в SystemBus
- `start()`:
  - подготовка к исполнению (пока пусто)
- `stop()`:
  - завершение (пока пусто)

На текущем этапе Scheduler **не имеет собственного потока**.

---

## 7. Использование в main loop

Пример упрощённого цикла:

```cpp
auto scheduler = bus.getService<Scheduler>();

while (running) {
    scheduler->tick();
}
```

В текущей реализации цикл ограничен фиксированным числом итераций
и вызывается из `main.cpp`.

---

## 8. Ограничения текущей реализации

Осознанные ограничения:

- нет периодов
- нет приоритетов
- нет защиты от долгих tick()
- нет статистики времени

Все эти возможности будут добавляться **поверх текущей модели**,
без её разрушения.

---

## 9. Связь с будущими подсистемами

Scheduler является базой для:

- Task Manager (группировка задач)
- IEC Task / Program execution
- I/O scan cycles
- Communication polling

Любая будущая модель исполнения будет опираться на Scheduler.
