# IO Binding — Architecture Skeleton

## 1. Назначение документа

Данный документ описывает архитектурный каркас подсистемы привязки ввода/вывода (IO Binding)
в проекте **system** на этапе ШАГА 15.

Документ фиксирует:
- роль IO Binding в IEC Runtime
- основные сущности
- границы ответственности

Реальная работа с устройствами и шинами в документе не рассматривается.

---

## 2. Общая концепция IO Binding

IO Binding предназначен для:
- связывания переменных IEC с внешним миром
- изоляции IEC Runtime от конкретного IO
- подготовки к аппаратной и симулированной интеграции

IO Binding:
- не содержит бизнес-логики
- не знает о Scheduler
- работает строго в рамках tick-loop

---

## 3. IecIoEndpoint

`IecIoEndpoint` — абстрактный источник или приёмник данных.

Назначение:
- чтение данных во `VAR_INPUT`
- запись данных из `VAR_OUTPUT`

Интерфейс:
```cpp
class IecIoEndpoint {
public:
    virtual void read(IecValueRef target) = 0;
    virtual void write(IecValueRef source) = 0;
};
```

Endpoint:
- не владеет значением
- не хранит состояние IEC
- реализуется на уровне System Layer

---

## 4. IecIoBinding

`IecIoBinding` управляет всеми связями IO в рамках одного Program.

Ответственность:
- хранение input/output bindings
- последовательное чтение входов
- последовательная запись выходов

IO Binding:
- не выполняет преобразований типов
- не знает о семантике значений
- работает с `IecValueRef`

---

## 5. Связь с IecProgram

Каждый `IecProgram`:
- владеет своим `IecIoBinding`
- вызывает его в `tick()`

Порядок выполнения:
1. `readInputs()`
2. execution engine
3. `writeOutputs()`

Это обеспечивает:
- детерминизм
- предсказуемый доступ к IO

---

## 6. Детерминизм и безопасность

Модель IO Binding проектируется с учётом:
- отсутствия скрытой асинхронности
- отсутствия блокировок
- строгого порядка операций

Любой реальный IO:
- должен быть адаптирован к этой модели
- не должен нарушать tick-loop

---

## 7. Ограничения текущего этапа

На текущем этапе отсутствуют:
- реальные IO endpoints
- буферизация
- преобразование типов
- обработка ошибок IO

Все ограничения являются **осознанными**.
