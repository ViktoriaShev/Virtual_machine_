# IEC Memory — Architecture Skeleton

## 1. Назначение документа

Данный документ описывает архитектурный каркас модели памяти IEC
в проекте **system** на этапе ШАГА 9.

Документ фиксирует:
- структуру памяти
- основные сущности
- правила владения и доступа

Реальная реализация типов и значений IEC в документе не рассматривается.

---

## 2. Общая концепция памяти IEC

Модель памяти IEC отражает стандарт IEC 61131-3 и предназначена для:
- хранения переменных Program
- разделения областей данных
- подготовки к привязке ввода/вывода

Память IEC:
- принадлежит Program
- не является глобальной
- не разделяется напрямую между Program

---

## 3. Области памяти

### 3.1 VAR

Область **VAR**:
- внутренние переменные Program
- сохраняют состояние между циклами
- недоступны напрямую извне

Использование:
- счётчики
- флаги
- внутренние состояния FB

---

### 3.2 VAR_INPUT

Область **VAR_INPUT**:
- входные переменные Program
- обновляются до выполнения Program
- отражают состояние внешнего мира

На текущем этапе:
- не привязаны к реальному IO
- обновление не реализовано

---

### 3.3 VAR_OUTPUT

Область **VAR_OUTPUT**:
- выходные переменные Program
- обновляются в процессе выполнения
- предназначены для передачи наружу

На текущем этапе:
- не привязаны к IO
- не распространяются автоматически

---

## 4. IecVariable

`IecVariable` — минимальное представление переменной IEC.

Текущие свойства:
- имя переменной

Планируемые расширения:
- тип IEC
- значение
- адрес
- атрибуты (retain, constant и т.д.)

---

## 5. IecMemory

`IecMemory` агрегирует переменные Program.

Содержит:
- список VAR
- список VAR_INPUT
- список VAR_OUTPUT

Ответственность:
- хранение структуры памяти
- предоставление доступа Program

`IecMemory`:
- не выполняет логику
- не знает о Scheduler
- не управляет синхронизацией

---

## 6. Связь с IecProgram

Каждый `IecProgram`:
- владеет экземпляром `IecMemory`
- управляет жизненным циклом памяти
- использует память в `tick()`

Таким образом:
- память строго локальна Program
- исключено неявное разделение состояния

---

## 7. Детерминизм и безопасность

Модель памяти проектируется с учётом:
- детерминированного доступа
- отсутствия гонок
- предсказуемого обновления данных

Любая многопоточность:
- должна быть вынесена за пределы IEC Runtime
- не должна нарушать модель tick-loop

---

## 8. Ограничения текущего этапа

На текущем этапе отсутствуют:
- значения переменных
- типизация IEC
- адресация
- IO binding
- retain / persistent storage

Все ограничения являются **осознанными**.
