# IEC Execution Engine — Architecture Skeleton

## 1. Назначение документа

Данный документ описывает архитектурный каркас движка исполнения IEC
в проекте **system** на этапе ШАГА 13.

Документ фиксирует:
- структуру execution engine
- роли основных компонентов
- порядок выполнения логики IEC

Реальная семантика выполнения и вычислений не рассматривается.

---

## 2. Общая концепция исполнения IEC

IEC Execution Engine отвечает за:
- упорядоченное выполнение выражений
- управление циклом исполнения Program
- изоляцию execution logic от Scheduler

Execution Engine:
- не управляет временем
- не знает о Scheduler напрямую
- вызывается из `IecProgram::tick()`

---

## 3. Execution Context

`IecExecutionContext` представляет контекст выполнения одного цикла.

Назначение:
- хранение состояния выполнения
- точка расширения для диагностики
- подготовка к breakpoint / tracing

Текущая версия:
- содержит только begin / end hooks
- не хранит состояние

---

## 4. Execution Engine

`IecExecutionEngine`:
- хранит список выражений
- выполняет их в фиксированном порядке
- управляет границами цикла исполнения

Упрощённая модель:

```cpp
beginCycle
  evaluate(expr1)
  evaluate(expr2)
  ...
endCycle
```

---

## 5. Связь с IecProgram

Каждый `IecProgram`:
- владеет своим Execution Engine
- владеет своим Execution Context
- инициирует выполнение в `tick()`

Таким образом:
- Program полностью контролирует свою логику
- Execution Engine не является глобальным

---

## 6. Детерминизм

Модель исполнения проектируется с учётом:
- строгого порядка выражений
- отсутствия скрытых side effects
- воспроизводимости поведения

Никакое динамическое перепланирование
на данном этапе не допускается.

---

## 7. Ограничения текущего этапа

На текущем этапе отсутствуют:
- обработка ошибок
- диагностика
- breakpoints
- online changes
- оптимизация порядка выполнения

Все ограничения являются **осознанными**.
