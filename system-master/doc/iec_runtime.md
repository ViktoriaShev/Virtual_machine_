# IEC Runtime — Architecture Skeleton

## 1. Назначение документа

Данный документ описывает архитектурный каркас IEC Runtime в проекте **system**
на этапе ШАГА 8.

Документ фиксирует:
- терминологию
- роли основных сущностей
- границы ответственности

Реализация IEC-логики в данном документе **не рассматривается**.

---

## 2. Общая концепция IEC Runtime

IEC Runtime — это подсистема исполнения IEC 61131-3 приложений,
построенная поверх базовых механизмов runtime:

- Scheduler
- Task Manager
- Event System
- SystemBus

IEC Runtime **не является отдельным процессом** и не нарушает
детерминированную модель исполнения system.

---

## 3. Основные сущности

### 3.1 IEC Task

IEC Task представляет собой логическую единицу исполнения,
соответствующую понятию *Task* в IEC 61131-3.

Свойства (планируемые):
- период (cycle time)
- приоритет
- watchdog
- режим запуска (cyclic / event)

На текущем этапе IEC Task является обёрткой над `Task`.

---

### 3.2 IEC Program

IEC Program:
- исполняется внутри IEC Task
- реализуется как `ITickable`
- вызывается в каждом цикле Task

IEC Program в текущей версии:
- не содержит IEC-кода
- служит каркасом для будущей реализации

---

### 3.3 Function Block (FB)

Function Block (планируется):
- часть IEC Program
- имеет собственное состояние
- вызывается в контексте Program

FB execution будет встроено в `IecProgram::tick()`.

---

## 4. Модель исполнения

Упрощённая цепочка исполнения:

```
Scheduler
  -> Task
      -> IEC Task
          -> IEC Program
              -> Function Blocks
```

Каждый уровень:
- не знает о вышележащих деталях
- выполняет строго свою ответственность

---

## 5. Интеграция с Task Manager

IEC Runtime:
- не управляет созданием Scheduler
- не управляет временем напрямую
- использует Task Manager для регистрации задач

Таким образом сохраняется:
- инверсия зависимостей
- единая модель исполнения

---

## 6. Детерминизм

IEC Runtime проектируется с приоритетом:
- детерминированного исполнения
- повторяемости поведения
- отсутствия скрытой асинхронности

Любая асинхронность:
- должна быть вынесена в System Layer
- не нарушать модель tick-loop

---

## 7. Ограничения текущего этапа

На текущем этапе отсутствуют:
- IEC memory model
- parsing / compilation IEC
- online changes
- breakpoints
- diagnostics

Все ограничения являются **осознанными**.
