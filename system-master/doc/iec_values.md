# IEC Values — Architecture Skeleton

## 1. Назначение документа

Данный документ описывает архитектурный каркас хранения значений IEC
в проекте **system** на этапе ШАГА 11.

Документ фиксирует:
- разделение type и value
- роль value storage
- правила связывания переменных со значениями

Реальная реализация значений и операций в документе не рассматривается.

---

## 2. Общая концепция Value Storage

Хранилище значений IEC предназначено для:
- хранения текущего состояния переменных
- отделения данных от логики исполнения
- обеспечения детерминированного доступа

Value Storage:
- не знает о Scheduler
- не знает о Task
- используется только через ссылки

---

## 3. IecValue

`IecValue` — базовый класс хранения значения IEC.

Свойства:
- содержит ссылку на `IecType`
- не определяет формат хранения
- не реализует операции

```cpp
class IecValue {
public:
    explicit IecValue(const IecType& type);
};
```

`IecValue`:
- служит базовым интерфейсом
- расширяется конкретными типами значений (BOOL, INT, …)

---

## 4. IecValueRef

`IecValueRef` — лёгкая ссылка на объект `IecValue`.

Назначение:
- передача доступа к значению
- отсутствие владения
- минимальные накладные расходы

Используется:
- в `IecVariable`
- в будущем — в выражениях и FB

---

## 5. Связь с IecVariable

Каждая `IecVariable`:
- имеет тип (`IecType`)
- может быть связана с `IecValue` через `IecValueRef`

Таким образом:
- объявление переменной отделено от её состояния
- возможна переалокация и переназначение значений

---

## 6. Жизненный цикл значений

На текущем этапе:
- создание `IecValue` не автоматизировано
- владение значениями не стандартизировано
- связывание выполняется вручную

Это осознанное ограничение каркасного этапа.

---

## 7. Детерминизм и безопасность

Модель значений проектируется с учётом:
- отсутствия динамической типизации
- отсутствия implicit conversions
- строгой предсказуемости доступа

Любые изменения значений:
- должны быть явными
- происходить в контексте tick-loop

---

## 8. Ограничения текущего этапа

На текущем этапе отсутствуют:
- конкретные реализации значений (BOOL, INT, REAL)
- операции чтения/записи
- копирование и сравнение
- инициализация значений

Все ограничения являются **осознанными**.

---
