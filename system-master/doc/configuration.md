# Configuration / Static Description — Architecture Skeleton

## 1. Назначение документа

Данный документ описывает архитектурный каркас слоя конфигурации
в проекте **system** на этапе ШАГА 18.

Документ фиксирует:
- назначение конфигурационного слоя
- модель статического описания системы
- способ применения конфигурации

Реальные форматы конфигурации и парсинг не рассматриваются.

---

## 2. Общая концепция Configuration Layer

Configuration Layer предназначен для:
- декларативного описания структуры системы
- отделения конфигурации от runtime-логики
- подготовки к внешним конфигурационным источникам

Конфигурация:
- создаётся до запуска runtime
- не изменяется во время исполнения
- применяется централизованно

---

## 3. SystemConfig

`SystemConfig` представляет статическое описание системы.

Содержит:
- список устройств (DeviceConfig)
- список fieldbus (FieldbusConfig)

`SystemConfig`:
- не знает о runtime
- не создает объектов
- хранит только описание

---

## 4. DeviceConfig и FieldbusConfig

`DeviceConfig` описывает устройство:
- логическое имя
- тип устройства (в будущем)

`FieldbusConfig` описывает коммуникационную шину:
- логическое имя
- тип транспорта (в будущем)

На текущем этапе:
- конфигурации минимальны
- расширение предусмотрено архитектурно

---

## 5. ConfigApplier

`ConfigApplier` — мост между конфигурацией и System Layer.

Ответственность:
- создание runtime-объектов на основе конфигурации
- применение конфигурации строго в одном месте

ConfigApplier:
- знает о DeviceManager и FieldbusManager
- не знает о IEC Runtime
- не хранит состояние

---

## 6. Место в архитектуре

Упрощённая схема:

```
Configuration
    ↓
ConfigApplier
    ↓
System Layer
    ↓
IEC Runtime
```

Это обеспечивает:
- слабую связность
- явный жизненный цикл
- тестируемость

---

## 7. Детерминизм

Конфигурация:
- применяется один раз
- до старта системы
- в фиксированном порядке

Во время исполнения:
- конфигурация не меняется
- runtime остаётся детерминированным

---

## 8. Ограничения текущего этапа

На текущем этапе отсутствуют:
- загрузка из файлов
- валидация конфигурации
- динамическое изменение
- профили конфигурации

Все ограничения являются **осознанными**.
